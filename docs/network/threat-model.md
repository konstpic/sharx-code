# SharX Network: границы защиты

Координатор — доверенный оператор. Его серверный код, PostgreSQL-схема,
экономика, админка и интеграционный стенд находятся только в приватном GitLab:
https://gitlab.sharxconnect.app/kpichugin/sharx-coordinator

## Действующие ограничения

- mTLS участника, отзыв сертификатов, общие PostgreSQL nonce/idempotency и
  транзакционная блокировка работают между репликами координатора.
- Оператор задаёт общий тариф; новый контракт фиксирует тариф, квоту в байтах,
  максимальную скорость и ключи панели/ноды. Объём и деньги считаются целыми
  числами. Полный заработок удерживается семь суток; заморозка безопасности и
  открытый спор запрещают автоматическую выплату. Возврат и выплата одной
  удержанной суммы взаимоисключающие. Старые контракты переходят в проверку.
- Приём новых сессий учитывает уже зарезервированные скорости даже при
  заниженном heartbeat. Это консервативный бюджет допуска, а не гарантия
  выделенной полосы каждому клиенту. Параметры активного контракта неизменяемы.
- Ограничение оборота пары учитывает оба направления за скользящие семь суток;
  отдельный лимит участника ограничивает разбиение оборота между контрагентами.
  Учитываются уже принятые обязательства по ещё неиспользованному резерву.
- Свидетельства привязаны к ключам контракта, времени, последовательности и
  уникальному nonce; явно невозможный по времени/скорости объём отклоняется.
- Audit-v2 связывает подпись свидетеля с полной задачей. Три разных ключа и
  оператора, кворум два из трёх. Повтор ключа не создаёт второго голоса.
  Поздний отрицательный результат добавляет исправление в прозрачный журнал,
  останавливает сессию и замораживает удержания до рассмотрения оператором.
- Реальные kernel QoS и изолированный network-inbound проверялись в Linux-стенде;
  это не аппаратная аттестация и не гарантия против владельца хоста с root.

## Чего эти механизмы не доказывают

Проверочный VLESS challenge подтверждает доступность пути, но не каждый байт
клиентского трафика. Подпись подтверждает источник счётчика, а не истинность
измерения. Встроенный программный валидатор перед ядром полезен для локальных
проверок, но root может заменить его или ядро; этот валидатор пока не реализован.

Без независимого доверенного измерителя на пути, подтверждений со стороны
самостоятельно измеряющего покупателя или подходящей аппаратной аттестации
нельзя исключить правдоподобные ложные счётчики и сговор. Сохранение общего
числа кредитов ограничивает эмиссионный ущерб, но само по себе не защищает
конкретного покупателя от ложного списания внутри его резерва.

Операторский relay пользователем отклонён; прямой путь сохраняется.
Процессы с разными ключами, которыми управляет один оператор, не становятся
независимыми владельцами. До настройки реальных независимых свидетелей
кластер стартует с bootstrap lock, запрещающим новые назначения даже после
попытки снять обычный emergency-флаг через API.

Для запуска платной эксплуатации необходимы независимые владельцы свидетелей,
проверенная процедура восстановления CA/БД и решение оставшегося доверия к
объёму. Изоляция и приватный репозиторий не заменяют эти условия.
