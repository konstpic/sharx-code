# 6. Хосты

[← Ноды](./05-nody.md) | [Оглавление](./README.md) | [Клиенты →](./07-klienty.md)

## Что такое хост

**Хост (Host)** — публичное имя, домен или CDN-точка, которую клиент видит в **подписке** вместо или вместе с «сырым» IP-адресом ноды.

Хост **не заменяет ноду** и **не принимает трафик сам по себе**. Нода по-прежнему обрабатывает соединения. Хост только меняет то, **какой адрес, порт и TLS-параметры** попадут в ссылку `vless://`, `vmess://` и т.д.

### Когда нужны хосты

| Ситуация | Зачем хост |
|----------|------------|
| Нода за **reverse proxy** (nginx, Caddy, HAProxy) | В подписке — домен прокси, на ноде Xray слушает локально |
| Трафик через **Cloudflare CDN** | В подписке — домен за CDN с WS/gRPC |
| **Балансировщик** перед несколькими нодами | Один домен → несколько backend'ов |
| Скрыть реальный IP ноды | Клиент видит только CDN-домен |
| Разные домены для регионов | Хост `eu.cdn.example.com` и `us.cdn.example.com` на одни inbound'ы |
| TLS-терминатор перед Xray | Xray без TLS, в ссылке `security=tls` (см. переопределения) |

### Предварительные условия

Раздел **Хосты** (`/panel/hosts/`) доступен **только** при включённом **режиме Multi-Node**:

1. **Настройки → Общие** → включить **Режим Multi-Node**.
2. Добавить и подключить **ноды**.
3. На inbound'ах **назначить ноды** (шаг «Ноды» при создании подключения).

Без этого в интерфейсе появится сообщение: *«Для управления хостами должен быть включен режим Multi-Node»*.

## Список хостов

Страница **Хосты** (`/panel/hosts/`):

| Колонка | Описание |
|---------|----------|
| **Имя** | Название хоста (для администратора) |
| **Адрес** | Публичный домен или IP |
| **Порт** | Порт в подписке (`0` = брать из inbound) |
| **Протокол** | Опциональное переопределение протокола |
| **Назначенные подключения** | Список привязанных inbound'ов |
| **Включено** | Активен ли хост |
| **Адреса в подписке** | Режим: Replace / Prepend / Append |

Кнопка **?** в шапке — встроенная справка по разделу.

## Создание хоста (пошагово)

### Шаг 1. Открыть форму

**Хосты** → **Добавить новый хост**.

### Шаг 2. Вкладка «Основные»

| Поле | Обязательно | Описание |
|------|-------------|----------|
| **Имя хоста** | Да | Произвольное имя (`CDN-EU`, `Cloudflare-main`) |
| **Адрес хоста** | Да | Домен или IP, который увидит клиент (`cdn.example.com`) |
| **Порт** | Нет | Порт в подписке. **0** — использовать порт inbound'а |
| **Протокол** | Нет | Переопределение протокола (редко нужно) |
| **Примечание** | Нет | Комментарий |
| **Включено** | — | Выключенный хост не участвует в подписке |

#### Выбор inbound'ов

Нажмите **Выбрать inbounds** — отметьте одно или несколько **подключений**, к которым применяется этот хост.

Хост влияет только на подписки клиентов, у которых назначены эти inbound'ы.

#### Режим «Адреса в подписке»

Определяет, как адрес хоста объединяется со строками нод:

| Режим | В интерфейсе | Результат в подписке |
|-------|--------------|----------------------|
| **replace** | Заменить адреса нод | Клиент видит **только** адрес хоста; строки нод скрыты |
| **prepend** | Добавить перед нодами | Сначала строка с хостом, затем строки нод |
| **append** | Добавить после нод | Сначала строки нод, затем строка с хостом |

**Пример** (inbound на 2 нодах: DE, NL):

```
Режим replace:
  → cdn.example.com:443          (только хост)

Режим prepend:
  → cdn.example.com:443          (хост)
  → 185.x.x.x:443 🇩🇪 DE         (нода 1)
  → 91.x.x.x:443 🇳🇱 NL          (нода 2)

Режим append:
  → 185.x.x.x:443 🇩🇪 DE
  → 91.x.x.x:443 🇳🇱 NL
  → cdn.example.com:443          (хост)
```

> **Replace** — типичный выбор для CDN: клиент подключается только через домен.
> **Prepend/Append** — когда нужен и CDN, и прямой доступ к нодам (резерв, тест).

### Шаг 3. Сохранить

Нажмите **Добавить хост**. Хост появится в списке.

### Шаг 4. Вкладка «Расширенные» (после создания)

При **создании** хоста вкладка «Расширенные» содержит только переопределения TLS/транспорта. Порядок нод и публикуемые адреса настраиваются **после сохранения**:

**Изменить хост** → вкладка **Расширенные**.

## Расширенные настройки

### Переопределения TLS и транспорта в ссылках

Секция **«Переопределения в ссылках подписки (TLS / транспорт)»**.

> Действуют **только** для строк подписки с **адресом этого хоста** (и external proxy). Строки нод в режимах prepend/append **сохраняют** TLS и транспорт из inbound'а.

| Поле | Описание |
|------|----------|
| **SNI (TLS / Reality)** | Server Name Indication в ссылке. Пусто — из inbound |
| **HTTP Host** | Заголовок Host для WS / gRPC / xhttp |
| **Путь / имя сервиса gRPC** | Path WebSocket или serviceName gRPC |
| **ALPN** | Через запятую: `h2,http/1.1` |
| **Отпечаток TLS (fp)** | chrome, firefox, safari и др. |
| **Разрешить небезопасный TLS** | Как в inbound / Да / Нет |
| **Принудительный TLS в ссылке** | Наследовать / Force TLS / Force none |

#### Принудительный TLS — типичный кейс

Когда **TLS-терминатор** (Caddy, nginx, HAProxy, Cloudflare) принимает HTTPS, а Xray на ноде слушает **без TLS**:

| На ноде (inbound) | В ссылке подписки |
|-------------------|-------------------|
| `security: none` | `security=tls` (Force TLS) |

И наоборот: Xray с TLS, а снаружи plain TCP — **Force none**.

### Строки подписки (ноды)

Секция появляется при редактировании хоста, если выбраны inbound'ы с назначенными нодами.

| Элемент | Описание |
|---------|----------|
| **Список строк** | По одной строке на каждую привязку inbound ↔ нода |
| **Порядок** | Кнопки «Выше» / «Ниже» — порядок в подписке |
| **Опубликованный адрес** | Адрес для этой строки (переопределяет адрес ноды) |
| **Опубликованный порт** | Порт для этой строки |
| **Включить в подписку** | Показывать ли эту строку |
| **Суффикс примечания** | Дополнение к имени сервера (`🇩🇪`, `-backup`) |

Кнопка **Обновить список** — перезагрузить строки после изменения inbound'ов хоста.

Если на inbound нет нод — сообщение: *«На этом inbound нет нод — назначьте ноды в разделе Inbounds»*.

## Практические сценарии

### Сценарий 1: Cloudflare + VLESS + WebSocket

**Инфраструктура:**
- Нода: Xray слушает `127.0.0.1:10000`, WS path `/ws`, без TLS.
- Cloudflare: `cdn.example.com` → прокси на ноду, SSL Full.

**Настройка хоста:**

| Поле | Значение |
|------|----------|
| Адрес | `cdn.example.com` |
| Порт | `443` |
| Режим | **replace** |
| HTTP Host | `cdn.example.com` |
| Путь | `/ws` |
| Force TLS | **Force TLS** |
| Inbound'ы | VLESS-WS inbound |

**Результат:** клиент получает ссылку на `cdn.example.com:443` с `security=tls`, path `/ws`.

---

### Сценарий 2: Прямой доступ + CDN (резерв)

**Задача:** основной вход через CDN, запасной — прямо на ноду.

| Поле | Значение |
|------|----------|
| Режим | **prepend** |
| Адрес хоста | `cdn.example.com:443` |

**Результат в подписке:**
1. `cdn.example.com` (через CDN)
2. `185.x.x.x` (прямо на ноду)

---

### Сценарий 3: REALITY за nginx stream

**Инфраструктура:**
- Xray: REALITY на порту 443 ноды.
- Снаружи: nginx stream passthrough на тот же порт.
- Клиенты подключаются по домену `proxy.example.com`.

| Поле | Значение |
|------|----------|
| Адрес | `proxy.example.com` |
| Порт | `443` |
| Режим | **replace** |
| SNI | `www.microsoft.com` (из REALITY inbound) |

Переопределения SNI берутся из inbound, если не заданы на хосте.

---

### Сценарий 4: Несколько хостов на разные inbound'ы

| Хост | Inbound | Назначение |
|------|---------|------------|
| `eu.cdn.com` | VLESS-EU | Европейский CDN |
| `us.cdn.com` | VLESS-US | Американский CDN |
| `tg.cdn.com` | Telemt | MTProto через CDN |

Один клиент с обоими inbound'ами увидит строки обоих хостов.

## Редактирование и удаление

### Редактирование

**Действия** → **Редактировать хост**:

- Вкладка **Основные** — имя, адрес, порт, inbound'ы, режим;
- Вкладка **Расширенные** — TLS-переопределения и порядок строк нод.

Изменения вступают в силу при следующем обновлении подписки клиентом.

### Включение / выключение

Переключатель **Включено** — быстро отключить хост без удаления. Выключенный хост не участвует в формировании подписки.

### Удаление

**Удалить хост** → подтверждение. Inbound'ы и ноды **не удаляются** — только запись хоста.

## Связь с другими разделами

```
Inbound (протокол, порт, TLS на ноде)
    │
    ├── Ноды (где слушает Xray, опубликованный адрес ноды)
    │
    └── Хосты (что видит клиент в подписке)
            │
            ▼
        Подписка клиента
```

| Настройка | Где задаётся | Что влияет |
|-----------|--------------|------------|
| Протокол, UUID, flow | Inbound + Клиент | Тип ссылки |
| Порт прослушивания Xray | Inbound | Реальный порт на ноде |
| Адрес ноды в подписке | Inbound → Ноды | IP ноды в строке |
| Публичный домен | **Хост** | Домен в строке хоста |
| TLS в ссылке | Inbound или **Хост** (override) | `security=` в URI |
| Порядок серверов | **Хост** → Расширенные | Порядок строк |

## Устранение неполадок

| Проблема | Возможная причина | Решение |
|----------|-------------------|---------|
| Хосты не отображаются | Multi-Node выключен | Включить в Настройках → Общие |
| Пустая подписка | Нет inbound'ов у клиента / хост выключен | Проверить клиента и флаг «Включено» |
| Клиент не подключается через CDN | Неверный path / Host / TLS | Проверить переопределения на вкладке «Расширенные» |
| Дублируются строки | Режим prepend/append + replace на другом хосте | Проверить режимы всех хостов |
| «Нет нод на inbound» | Inbound не привязан к нодам | Подключения → редактировать → шаг «Ноды» |
| TLS mismatch | Force TLS/none не соответствует инфраструктуре | Согласовать с reverse proxy |

---

## Рекомендации

1. Начните с режима **replace** — проще отладить одну строку.
2. **Не дублируйте** TLS-настройки: сначала настройте inbound, переопределяйте на хосте только то, что отличается (домен, path, security).
3. После изменения inbound'ов хоста нажимайте **Обновить список** на вкладке «Расширенные».
4. Тестируйте подписку в целевом приложении (Happ, v2rayNG), а не только в браузере.
5. Для Cloudflare: оранжевое облако (прокси) + WS/gRPC; REALITY через CF требует отдельной схемы.
