# 5. Ноды

[← Подключения](./04-podklyucheniya.md) | [Оглавление](./README.md) | [Хосты →](./06-hosty.md)

## Что такое нода

**Нода (Node)** — удалённый сервер с воркером SharX и Xray, который обрабатывает трафик клиентов. Панель управляет нодами централизованно: отправляет конфигурацию, проверяет состояние, собирает статистику.

Ноды используются только в режиме **Multi-Node**.

## Включение режима Multi-Node

1. Перейдите в **Настройки → Общие**.
2. Включите переключатель **Режим Multi-Node**.
3. Сохраните настройки.

После включения:

- Xray **не запускается** на сервере панели;
- конфигурации **отправляются** на воркер-ноды;
- inbound'ы **должны быть назначены** на ноды;
- подписки используют **адреса нод** (или хостов).

В боковом меню появится раздел **Ноды** с подразделами: Управление, Статистика, География.

## Добавление ноды

Страница **Ноды** (`/panel/nodes/`) → **Добавить ноду**.

Мастер состоит из трёх шагов.

### Шаг 1. Новая нода

| Поле | Описание |
|------|----------|
| **Имя ноды** | Уникальное имя (можно с флагом страны 🇩🇪🇺🇸) |
| **Адрес / URL** | IP или домен сервера ноды |
| **Порт** | Порт API воркера (по умолчанию **8080**) |
| **TLS** | Использовать HTTPS для API |
| **Лимит трафика (ГБ)** | 0 = без ограничения |

### Шаг 2. Регистрация

Два подшага:

#### 2.1. Зарегистрировать в панели

Нажмите **Создать запись ноды** (или аналогичную кнопку на подшаге).

Панель:
1. Создаёт запись в базе данных.
2. Генерирует **SECRET_KEY** — base64 JSON bundle (TLS, mTLS, JWT).
3. Показывает готовый **`docker-compose.yml`**:

```yaml
# фрагмент — реальные значения подставляются автоматически
services:
  sharx-node:
    environment:
      PANEL_URL: https://panel.example.com
      SECRET_KEY: eyJ...base64...
```

**Действия:**
1. Нажмите **Копировать** у блока compose.
2. Не редактируйте `SECRET_KEY` вручную.

#### 2.2. Подключить ноду

На **сервере ноды** (отдельная VPS):

```bash
# 1. Подготовить директорию
mkdir -p ~/sharx-node && cd ~/sharx-node

# 2. Создать compose-файл
nano docker-compose.yml
# Вставить скопированное содержимое, сохранить (Ctrl+O, Enter, Ctrl+X)

# 3. Запустить
docker compose up -d --build

# 4. Проверить логи
docker compose logs -f
```

**Требования к серверу ноды:**
- Linux с Docker;
- открыты порты inbound'ов (443, 10000 и т.д.);
- `/dev/net/tun` (для VPN-протоколов);
- исходящий доступ к `PANEL_URL` панели.

Вернитесь в панель → нажмите **Проверить** (health-check).

**Успех:** статус **online**, Xray — **Running**.

**Ошибка offline:**
- панель не достучится до `адрес:8080` ноды;
- неверный `SECRET_KEY`;
- файрвол блокирует порт API ноды (8080) с IP панели.

### Шаг 3. Профиль Xray для ноды

Опционально назначьте **профиль конфигурации ядра** (Xray core config profile) для этой ноды:

- **Пропустить** — использовать профиль по умолчанию;
- **Назначить и закрыть** — привязать выбранный профиль.

## Развёртывание ноды вручную

Типовой `docker-compose.yml` ноды содержит:

```yaml
environment:
  SECRET_KEY: <base64 bundle из панели>
  PANEL_URL: https://panel.example.com
  NODE_ADDRESS: <публичный IP, если автоопределение не подходит>
```

- `network_mode: host` — рекомендуется;
- тома: `cert/`, `data/`, `logs/`;
- sidecar'ы Telemt и AmneziaWG при необходимости.

Подробности: `node/README.md`.

## Аутентификация нод

| Режим | Описание |
|-------|----------|
| **Pairing (рекомендуется)** | mTLS + JWT через `SECRET_KEY`. Безопасный обмен. |
| **Legacy** | Статический API-ключ (устаревший, для совместимости). |

В pairing-режиме отдельная ручная настройка TLS на ноде **не требуется** — всё задаётся бандлом `SECRET_KEY`.

## Список нод

Таблица / плитки с информацией:

| Поле | Описание |
|------|----------|
| **Статус** | `online` / `offline` / `unknown` — доступность API |
| **Xray** | Running / Stopped / Error — состояние ядра на ноде |
| **Telemt** | Состояние sidecar MTProto |
| **AmneziaWG** | Состояние sidecar AmneziaWG |
| **Трафик** | Загрузка / отдача |
| **Inbound'ы** | Назначенные подключения |
| **Профили** | Профили конфигурации ядра |

## Действия с нодой

| Действие | Описание |
|----------|----------|
| **Проверить** | Health-check API |
| **Перезагрузить конфиг** | Push конфигурации на ноду |
| **Остановить / Запустить Xray** | Управление ядром |
| **Остановить / Запустить Telemt** | Управление MTProto sidecar |
| **Остановить / Запустить AmneziaWG** | Управление AWG sidecar |
| **Редактировать** | Изменить имя, адрес, лимиты |
| **Отключить** | Временно остановить синхронизацию (без удаления) |
| **Удалить** | Удалить ноду из панели |

## Привязка inbound'ов к нодам

При создании или редактировании **подключения** (inbound) на шаге **Ноды**:

1. Выберите одну или несколько нод.
2. Для каждой привязки настройте:
   - **Включить в подписку** — показывать endpoint в подписке клиента;
   - **Опубликованный адрес** — адрес, который увидит клиент;
   - **Опубликованный порт** — порт в подписке;
   - **Суффикс примечания** — дополнение к имени сервера в подписке.

Один inbound может быть назначен на **несколько нод** — в подписке клиента появятся строки для каждой.

## Статистика и география

| Раздел | URL | Содержание |
|--------|-----|------------|
| **Статистика** | `/panel/nodes/statistics/` | Трафик, онлайн по нодам |
| **География** | `/panel/nodes/geography/` | Карта расположения нод |

## Лимит трафика ноды

Поле **Лимит трафика (ГБ)** на ноде ограничивает суммарный трафик через эту ноду. Значение `0` — без ограничения.

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| Нода offline | Проверьте, что контейнер запущен; порт API доступен с панели; файрвол |
| Ошибка pairing | Убедитесь, что `SECRET_KEY` и `PANEL_URL` скопированы из панели без изменений |
| Xray не запускается | Проверьте логи на ноде; убедитесь, что inbound'ы назначены |
| Панель не достучится до ноды | При HTTPS панели — доверие к CA на ноде; проверьте `NODE_ADDRESS` |

## Полный цикл: от панели до рабочей ноды

```
1. Настройки → Общие → включить Multi-Node
2. Ноды → Добавить ноду → заполнить имя и адрес
3. Шаг «Регистрация» → скопировать docker-compose.yml
4. На сервере ноды: docker compose up -d --build
5. В панели: «Проверить» → статус online
6. Подключения → создать inbound → шаг «Ноды» → выбрать эту ноду
7. (Опционально) Хосты → публичный домен для подписки
8. Клиенты → создать клиента → назначить inbound
9. Проверить подписку в клиентском приложении
```
