# 2. Установка

[← Обзор](./01-obzor.md) | [Оглавление](./README.md) | [Веб-интерфейс →](./03-veb-interfejs.md)

## Требования

- Linux-сервер (Ubuntu, Debian, CentOS, Fedora, Arch, Alpine, openSUSE)
- Root-доступ
- Свободные порты: **2053** (панель), **2096** (подписки), **80** (для SSL-сертификата)
- Docker и Docker Compose (устанавливаются автоматически скриптом или вручную)

---

## Вариант 1: Автоматическая установка (рекомендуется)

```bash
git clone https://github.com/konstpic/SharX.git
cd SharX
sudo ./install_ru.sh
```

Скрипт:

1. Определяет дистрибутив Linux и устанавливает Docker.
2. Предлагает выбрать режим сети: **host** или **bridge**.
3. Настраивает порты панели и подписок.
4. Генерирует пароль PostgreSQL.
5. Выпускает SSL-сертификат через Let's Encrypt (acme.sh).
6. Запускает все сервисы.

### Меню управления

После установки повторный запуск `sudo ./install_ru.sh` открывает меню:

- Установка / обновление / запуск / остановка / перезапуск панели
- Смена портов, пароля БД, сертификатов
- Просмотр логов и статуса
- Удаление

## Вариант 2: Ручная установка через Docker Compose

### Шаг 1. Клонирование репозитория

```bash
git clone https://github.com/konstpic/SharX.git
cd SharX
```

### Шаг 2. Настройка docker-compose.yml

Откройте `docker-compose.yml` и измените:

**Пароль базы данных** — замените `change_this_password` на надёжный пароль в обоих местах:

```yaml
XUI_DB_PASSWORD: ваш_надёжный_пароль
POSTGRES_PASSWORD: ваш_надёжный_пароль
```

Пароли **должны совпадать**.

**Порты** (при режиме bridge):

```yaml
ports:
  - "2053:2053"   # Веб-интерфейс
  - "2096:2096"   # Подписки
```

**Режим сети host** (рекомендуется для производительности):

```yaml
network_mode: host
```

При `network_mode: host` секцию `ports` удалите — порты открываются напрямую на хосте. Для подключения к PostgreSQL используйте `XUI_DB_HOST: 127.0.0.1`.

### Шаг 3. SSL-сертификаты

```bash
mkdir -p cert
cp /путь/к/fullchain.pem cert/cert.pem
cp /путь/к/privkey.pem cert/privkey.pem
```

Файлы монтируются в контейнер. В настройках панели указывайте пути:

- Сертификат: `/app/cert/cert.pem`
- Ключ: `/app/cert/privkey.pem`

### Шаг 4. Запуск

```bash
docker compose up -d
```

### Шаг 5. Первый вход

Откройте в браузере:

```
http://IP-вашего-сервера:2053
```

**Учётные данные по умолчанию:**

| Поле | Значение |
|------|----------|
| Логин | `admin` |
| Пароль | `admin` |

> Сразу после входа смените пароль: **Настройки → Администратор**.

### Шаг 6. Настройка TLS в панели

1. Перейдите в **Настройки → Общие**.
2. Укажите **доменное имя** (например, `panel.example.com`).
3. Укажите пути к сертификатам (см. выше).
4. Сохраните и перезапустите контейнер:

```bash
docker compose restart sharx
```

5. Откройте `https://panel.example.com:2053` и убедитесь, что сертификат валиден.

## Переменные окружения

Полный справочник: `ENV_VARIABLES.md` в корне репозитория.

### Основные переменные панели

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `XUI_WEB_PORT` | `2053` | Порт веб-интерфейса |
| `XUI_WEB_DOMAIN` | — | Домен панели |
| `XUI_WEB_BASE_PATH` | `/` | Базовый путь URL |
| `XUI_WEB_CERT_FILE` | — | Путь к SSL-сертификату |
| `XUI_WEB_KEY_FILE` | — | Путь к приватному ключу |
| `XUI_SUB_PORT` | `2096` | Порт сервиса подписок |
| `XUI_SUB_PATH` | `/sub/` | URI-путь подписки |
| `XUI_SUB_DOMAIN` | — | Домен для подписок |
| `XUI_DB_HOST` | `127.0.0.1` | Хост PostgreSQL |
| `XUI_DB_PASSWORD` | — | Пароль БД |

Эти параметры задаются **только через переменные окружения** и не редактируются в веб-интерфейсе.

## Обновление панели

В составе `docker-compose.yml` идёт **Watchtower** — сервис автообновления контейнеров.

**Из веб-интерфейса:** кнопка обновления в шапке панели (при корректно настроенном образе из реестра).

**Вручную:**

```bash
docker compose pull
docker compose up -d
```

**Через скрипт:**

```bash
sudo ./install_ru.sh
# → 2) Обновить панель
```

> Для production используйте готовый образ из реестра (например, `registry.konstpic.ru/sharx/sharx:версия`) вместо локальной сборки `build:`, иначе Watchtower не сможет подтянуть обновления.

## Установка нод (кратко)

Ноды устанавливаются **отдельно** на других серверах после настройки панели:

1. Включите **режим Multi-Node** в настройках панели.
2. Добавьте ноду через интерфейс — скопируйте `docker-compose.yml` с `PANEL_URL` и `SECRET_KEY`.
3. На сервере ноды: `docker compose up -d --build`.

Подробнее: [Ноды](./05-nody.md).

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| Панель не открывается | Проверьте `docker compose ps`, логи: `docker compose logs sharx` |
| Ошибка подключения к БД | Убедитесь, что `XUI_DB_PASSWORD` = `POSTGRES_PASSWORD`; при host-сети используйте `127.0.0.1` |
| SSL не работает | Проверьте пути `/app/cert/cert.pem` и `privkey.pem` внутри контейнера |
| Подписка недоступна | Проверьте порт 2096, `XUI_SUB_DOMAIN`, файрвол |
