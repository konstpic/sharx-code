# SharX — Руководство пользователя

**Версия документа:** 1.0 · **Панель:** 1.6.6 · **Язык:** русский

---

# 1. SharX

## Краткое описание

**SharX** — веб-панель для управления прокси- и VPN-подключениями на базе Xray. Через браузер администратор настраивает серверы, создаёт учётные записи клиентов, выдаёт подписки и контролирует трафик.

## Что делает сервис

- Создаёт и настраивает **подключения** (протоколы VLESS, VMess, Trojan, Shadowsocks и др.).
- Ведёт список **клиентов** — конечных пользователей, которым выдаётся доступ.
- Формирует **подписки** — ссылки и конфигурации для мобильных и десктопных приложений (Happ, v2rayNG, Clash и др.).
- Управляет **нодами** — удалёнными серверами, на которых обрабатывается трафик (в режиме Multi-Node).
- Настраивает **хосты** — публичные домены и CDN-адреса в подписках.
- Ограничивает доступ: лимиты трафика, срок действия, количество устройств (HWID), одновременные IP.
- Показывает статистику: онлайн, трафик, состояние серверов.

## Для кого предназначен

| Роль | Использование |
|------|---------------|
| **Администратор панели** | Ежедневная работа: клиенты, подключения, настройки |
| **Инженер инфраструктуры** | Установка панели, нод, SSL, резервное копирование |
| **Оператор поддержки** | Просмотр клиентов, сброс трафика, проверка подписок |

Конечные пользователи VPN **не работают в панели** — они получают ссылку подписки и настраивают клиентское приложение.

## Какие задачи решает

1. Централизованное управление множеством серверов и протоколов.
2. Выдача и отзыв доступа без ручной настройки каждого устройства.
3. Контроль расхода трафика и сроков подписки.
4. Защита от раздачи аккаунтов (HWID, лимит IP).
5. Брендированная страница подписки с инструкциями для клиентов.

# 2. Быстрый старт

## Что нужно администратору

| Требование | Описание |
|------------|----------|
| **Права** | Учётная запись администратора панели (логин и пароль) |
| **URL** | Адрес панели, например `https://panel.example.com:2053` |
| **Браузер** | Современный браузер (Chrome, Firefox, Safari, Edge). JavaScript обязателен |
| **Сеть** | Доступ к URL панели по HTTPS (рекомендуется) или HTTP |

Порты и домен задаются при установке системным администратором. В интерфейсе панели их можно **просмотреть** (Настройки → Панель и общее → Привязка панели), но **изменить нельзя** — только через конфигурацию сервера.

## Первый вход

1. Откройте URL панели в браузере.
2. На странице входа введите **Имя пользователя** и **Пароль**.
3. Нажмите **Войти**.
4. При включённой двухфакторной аутентификации (2FA) введите **Код 2FA** из приложения-аутентификатора или из Telegram.
5. После успешного входа откроется раздел **Обзор** (дашборд).

**Учётные данные по умолчанию** (только при первой установке, если не менялись):

| Поле | Значение |
|------|----------|
| Логин | `admin` |
| Пароль | `admin` |

Сразу после первого входа смените пароль: **Настройки → Админ и перезапуск → Смена логина и пароля**.

## Выбор языка

На странице входа и в **Настройки → Панель и общее → Язык интерфейса** можно выбрать язык панели.

## Минимальный рабочий цикл (один сервер)

1. **Подключения** → **Создать подключение** → выбрать протокол → **Сохранить**.
2. **Клиенты** → **Добавить клиента** → указать имя → выбрать подключение → **Сохранить**.
3. Скопировать ссылку подписки клиента и передать пользователю.
4. Пользователь добавляет ссылку в приложение (Happ, v2rayNG и т.д.).

## Минимальный цикл (несколько серверов, Multi-Node)

1. **Настройки → Панель и общее** → включить **Режим Multi-Node** → **Сохранить**.
2. **Ноды** → **Добавить ноду** → развернуть воркер по инструкции в мастере → **Проверить**.
3. **Подключения** → создать подключение → на шаге **Ноды** назначить сервер.
4. При необходимости: **Хосты** → добавить публичный домен для подписки.
5. **Клиенты** → создать клиента → назначить подключение.

# 3. Интерфейс

Панель состоит из **бокового меню** (слева), **шапки** (сверху) и **рабочей области** (центр).

## Шапка

| Элемент | Назначение |
|---------|------------|
| Название и версия | Идентификация панели, индикатор обновлений |
| Ссылки GitHub / Telegram / Donate | Внешние ресурсы проекта |

## Боковое меню

| Раздел | Когда используется |
|--------|-------------------|
| **Обзор** | Ежедневный контроль состояния системы |
| **Подключения** | Создание и настройка протоколов и портов |
| **Ноды** * | Управление удалёнными серверами (только Multi-Node) |
| **Хосты** | Публичные домены в подписках (только Multi-Node) |
| **Клиенты** | Учётные записи конечных пользователей |
| **Группы** | Группировка клиентов для массовых операций |
| **Настройки** | Конфигурация панели, подписки, безопасности |
| **Xray** | Расширенная настройка ядра прокси |
| **API Docs** | Справочник API (для автоматизации) |
| **Выход** | Завершение сессии |

\* Раздел **Ноды** виден только при включённом режиме Multi-Node.

---

## 3.1. Обзор (дашборд)

**Назначение:** сводное состояние панели, серверов и клиентов.

**Когда используется:** в начале рабочего дня, после изменений, при диагностике сбоев.

**Отображаемые данные:**

| Блок | Данные |
|------|--------|
| Ресурсы | Загрузка CPU, ОЗУ, диск, swap |
| Xray / Telemt | Запущен / остановлен, версия ядра |
| Быстрые действия | Журнал, конфигурация, резервная копия |
| Время работы | Uptime панели и системы |
| Пользователи онлайн | Число активных клиентов |
| База данных | Состояние PostgreSQL |
| Сеть | Скорость, TCP/UDP, IP-адреса |
| Доступность нод | Online/offline (Multi-Node) |

**Доступные действия:**

- **Настроить дашборд** — включить/выключить виджеты, **Сбросить раскладку**.
- **Остановить / Перезапустить Xray** (single-node).
- **Остановить Telemt**.
- **Журнал** — просмотр, фильтрация, экспорт логов.
- **Резервная копия** — экспорт/импорт базы данных.
- **История CPU / памяти** — графики за выбранный интервал.
- **Управление нодами** — переход в раздел Ноды.

---

## 3.2. Подключения

**Назначение:** настройка точек входа — протокол, порт, шифрование, транспорт.

**Когда используется:** при добавлении нового протокола, порта или сервера в подписку.

**Таблица:**

| Колонка | Содержание |
|---------|------------|
| Примечание | Имя подключения |
| Тег | Внутренний идентификатор для Xray |
| Протокол | VLESS, VMess, Trojan и др. |
| Хост | Порт прослушивания |
| Отправлено/получено | Суммарный трафик |
| Статус | Переключатель Вкл/Выкл |

**Действия:** создать, редактировать (клик по строке), удалить, фильтровать, сменить вид (таблица / список / плитки).

---

## 3.3. Ноды

**Назначение:** управление удалёнными серверами-воркерами.

**Когда используется:** при масштабировании, добавлении нового дата-центра, диагностике недоступности.

**Таблица (основные колонки):** Включена, Имя, Адрес, Статус, Состояние Xray, Sidecars (Telemt, AmneziaWG), Назначенные подключения, Действия.

**Действия:** добавить ноду (мастер из 3 шагов), проверить связь, остановить/перезапустить Xray и sidecar'ы, просмотр метрик CPU/RAM/Disk, удалить.

---

## 3.4. Хосты

**Назначение:** подмена адресов в подписке (домен CDN, reverse proxy).

**Когда используется:** когда клиент должен подключаться по домену, а не по IP ноды.

**Доступность:** только при включённом **Режиме Multi-Node**.

**Таблица:** Включено, Имя, Адрес, Порт, Протокол, Примечание, Назначенные подключения, Действия.

---

## 3.5. Клиенты

**Назначение:** учётные записи конечных пользователей VPN/прокси.

**Когда используется:** выдача и отзыв доступа, изменение лимитов, диагностика проблем пользователя.

**Сводка сверху:** Всего пользователей, Онлайн, Оффлайн, Показано по фильтрам.

**Таблица (настраиваемые столбцы):** ID, имя, комментарий, статус, трафик, срок, группа, подключения, UUID, Sub ID и др.

**Действия:** добавить, редактировать (боковая панель), массовые операции, фильтры, настройка видимости столбцов.

---

## 3.6. Группы

**Назначение:** объединение клиентов для массового изменения настроек.

**Таблица:** Название, Описание, Количество клиентов, Действия.

**Действия:** добавить группу, редактировать (массовые настройки всех клиентов группы), удалить.

---

## 3.7. Настройки

Вкладки:

| Вкладка | Назначение |
|---------|------------|
| **Панель и общее** | Язык, тема, сессия, Multi-Node, HWID, лимит IP, логи |
| **Безопасность** | 2FA, API-токены |
| **Telegram** | Бот для уведомлений |
| **Подписка и JSON** | Параметры подписки, конструктор страницы |
| **LDAP** | Внешняя аутентификация и синхронизация клиентов |
| **Grafana** | Интеграция с мониторингом |
| **Админ и перезапуск** | Смена пароля, перезапуск панели |

На всех вкладках: **Сбросить**, **Сохранить**. При несохранённых изменениях — баннер **Есть несохранённые изменения.**

---

## 3.8. Xray

**Назначение:** расширенная настройка конфигурации прокси-ядра.

**Вкладки:** Конфиг ядра, Итоговый JSON, Geo-файлы.

**Действия:** Сохранить, Сохранить и применить, сброс к умолчанию, перезапуск Xray, управление geoip/geosite.

---

## 3.9. Публичная страница подписки

**URL:** `/panel/sub/?id=<идентификатор подписки>`

**Назначение:** страница для конечного пользователя (без меню панели): статус, трафик, кнопки импорта в приложение, QR-коды.

**Настраивается** в **Настройки → Подписка и JSON → конструктор**.

# 4. Основные сценарии работы

## 4.1. Вход в панель

1. Откройте URL панели.
2. Введите **Имя пользователя** и **Пароль**.
3. Нажмите **Войти**.
4. При запросе 2FA — введите код и нажмите **Войти** снова.
5. Результат: открыт раздел **Обзор**, в шапке отображается версия.

---

## 4.2. Смена пароля администратора

1. Перейдите в **Настройки → Админ и перезапуск**.
2. Заполните **Текущий логин**, **Текущий пароль**, **Новый логин**, **Новый пароль**.
3. Нажмите **Обновить**.
4. Результат: сообщение об успешной смене учётных данных. **2FA будет отключена** — при необходимости включите заново.

---

## 4.3. Создание подключения (VLESS + REALITY)

1. **Подключения** → **Создать подключение**.
2. Шаг **Основное:** протокол **VLESS**, порт **443**, примечание `VLESS-REALITY`.
3. Шаг **Transport:** сеть **tcp**, безопасность **reality**, заполните Dest, Server Names, ключи REALITY.
4. Шаг **Auth:** при необходимости flow `xtls-rprx-vision`.
5. Шаг **Sniffing:** по желанию.
6. Шаг **Ноды** (Multi-Node): выберите сервер, включите **В подписке**.
7. Нажмите **Сохранить**.
8. Результат: подключение в списке со статусом **Включено**.

---

## 4.4. Добавление ноды

1. Убедитесь, что включён **Режим Multi-Node**.
2. **Ноды** → **Добавить ноду**.
3. Шаг 1: имя, адрес, порт API (обычно 8080).
4. Шаг 2: скопируйте **Docker Compose**, разверните на сервере ноды, нажмите **Проверить**.
5. Шаг 3: назначьте профиль Xray или **Пропустить**.
6. Результат: статус ноды **online**, Xray **Running**.

---

## 4.5. Создание хоста для CDN

1. **Хосты** → **Добавить хост**.
2. Вкладка **Основные:** имя, адрес `cdn.example.com`, порт `443`.
3. Выберите inbound'ы, режим **Заменить адреса нод**.
4. **Добавить хост**.
5. **Редактировать** → **Расширенные:** HTTP Host, Path, **Force TLS** при необходимости.
6. Результат: в подписке клиента адрес ноды заменён на домен CDN.

---

## 4.6. Создание клиента

1. **Клиенты** → **Добавить клиента**.
2. Укажите **имя** (латиница, уникальное).
3. Выберите одно или несколько **подключений**.
4. При необходимости: лимит трафика, срок, группа, HWID.
5. Нажмите **Сохранить**.
6. Результат: клиент в списке, UUID скопирован, доступна ссылка подписки.

---

## 4.7. Редактирование клиента

1. **Клиенты** → клик по строке клиента.
2. В боковой панели измените нужные поля (имя изменить **нельзя**).
3. Нажмите **Сохранить**.
4. Результат: **Клиент обновлён.**

---

## 4.8. Удаление клиента

1. Откройте карточку клиента **или** включите **Массовые действия**.
2. Нажмите **Удалить**.
3. Подтвердите в диалоге.
4. Результат: клиент удалён из списка, доступ по подписке прекращается.

---

## 4.9. Массовое назначение группы

1. **Клиенты** → **Массовые действия**.
2. Отметьте клиентов чекбоксами (или **Выбрать всех по фильтру**).
3. **Назначить группу** → выберите группу → подтвердите.
4. Результат: у выбранных клиентов обновлена группа.

---

## 4.10. Массовый сброс трафика

1. **Клиенты** → **Массовые действия** → выберите клиентов.
2. **Сбросить трафик** → подтвердите.
3. Результат: счётчики трафика обнулены.

---

## 4.11. Создание и настройка группы

1. **Группы** → **Добавить группу** → название (до 30 символов) → **Создать**.
2. **Редактировать группу** → измените срок, лимит трафика, inbound'ы, HWID — **Сохранить**.
3. Результат: настройки применены ко **всем клиентам** этой группы.

---

## 4.12. Поиск клиента

1. **Клиенты** → введите текст в поле поиска **или** откройте **Фильтры столбцов**.
2. Задайте условия (имя, группа, статус, трафик, срок).
3. Результат: таблица показывает только подходящих клиентов; плитка **Показано по фильтрам** обновляется.

---

## 4.13. Фильтрация подключений

1. **Подключения** → **Показать фильтры столбцов**.
2. Фильтруйте по примечанию, тегу, протоколу, порту, статусу.
3. **Сбросить фильтры** — вернуть полный список.

---

## 4.14. Экспорт резервной копии

1. **Обзор** → **Быстрые действия** → **Резервная копия**.
2. Нажмите **Экспорт базы данных**.
3. Результат: файл загружается на компьютер.

---

## 4.15. Экспорт журнала

1. **Обзор** → **Журнал**.
2. При необходимости задайте фильтры уровня и источника.
3. Нажмите **Экспорт**.
4. Результат: файл журнала сохранён.

---

## 4.16. Настройка страницы подписки

1. **Настройки → Подписка и JSON**.
2. В конструкторе: **Оформление** → логотип, цвета.
3. **Блоки** → добавьте subscription-info, add-to-app, links-list.
4. **Правила ответа** → Profile-Title, интервал обновления.
5. **Сохранить**.
6. Откройте `/panel/sub/?id=<subId>` тестового клиента для проверки.

---

## 4.17. Включение двухфакторной аутентификации

1. **Настройки → Безопасность**.
2. **Настроить приложение** → отсканируйте QR в Google Authenticator (или аналог).
3. Введите код подтверждения.
4. Результат: при следующем входе потребуется код 2FA.

---

## 4.18. Копирование подписки клиента

1. **Клиенты** → откройте клиента.
2. Нажмите **Открыть подписку** или иконку копирования ссылки.
3. Результат: ссылка в буфере обмена — передайте пользователю.

---

# 5. Элементы интерфейса по страницам

Ниже — ключевые элементы. Поля протокол-специфичных форм (REALITY, Hysteria, WireGuard) зависят от выбранного протокола; при сомнениях ориентируйтесь на подсказки (?) рядом с полем.

---

## 5.1. Страница входа

| Элемент | Назначение | Ограничения | После использования |
|---------|------------|-------------|---------------------|
| Имя пользователя | Логин администратора | Обязательное | — |
| Пароль | Пароль | Обязательное | — |
| Код 2FA | Код TOTP / Telegram | Обязателен, если включена 2FA | Вход в панель |
| Войти | Отправка формы | — | Переход на Обзор или сообщение об ошибке |
| Язык интерфейса | Выбор языка | — | Смена языка страницы |

---

## 5.2. Клиенты — форма создания/редактирования

| Поле | Назначение | Значения / ограничения | После сохранения |
|------|------------|------------------------|------------------|
| Имя клиента | Уникальный идентификатор | Обязательное; латиница; **не меняется** после создания | Используется в статистике и подписке |
| Комментарий | Заметка администратора | До 100 символов | Только в панели |
| UUID | Идентификатор протокола | Автогенерация; до 64 символов | В ссылках vless/vmess |
| Telegram ID | Уведомления бота | Число | Опционально |
| ID подписки | Ключ URL подписки | 16 символов; только при создании | В URL `/sub/...` |
| Срок | Дата окончания | Пусто = бессрочно | Статус EXPIRED после даты |
| Лимит трафика (ГБ) | Макс. трафик | 0 = безлимит | Статус LIMITED при превышении |
| Сброс (дни) | Период сброса счётчика | Число дней | Автосброс трафика |
| Подключения | Доступные серверы | Минимум 1 для рабочей подписки | Строки в подписке |
| Группа | Принадлежность | Одна или ни одной | Фильтрация, массовые операции |
| HWID | Лимит устройств | 0 = безлимит; бета, Happ/v2rayTun | Блокировка лишних устройств |
| Лимит IP | Одновременные IP | Мин. 1 при включении | Drop/block по настройкам |
| Объявление | Текст в подписке | До 200 символов | Заголовок Announce |

**Кнопки в карточке клиента:** Вкл/Выкл, Открыть подписку, QR, Ключи, Активные сессии (IP), Сбросить трафик, Очистить HWID, Удалить.

**Массовые действия:** Назначить группу, Сбросить трафик, Очистить HWID, Удалить.

# 7. Частые проблемы (FAQ)

### Почему подписка клиента пустая?

- Клиенту не назначено ни одно **подключение**.
- Подключение **выключено**.
- В Multi-Node: на inbound не назначены **ноды** или нода **offline**.
- Клиент **отключён**, **истёк** или **исчерпал трафик** (при включённых пользовательских примечаниях вместо серверов показывается заглушка).

### Почему клиент не подключается, хотя подписка есть?

- Неверные параметры TLS/Reality/WS на подключении или хосте.
- Порт закрыт файрволом на ноде.
- Для CDN: не совпадают Path, Host, режим SSL.
- HWID: превышен лимит устройств (403 или заглушка).

### Почему нельзя сохранить клиента?

- Пустое **имя**.
- Имя уже занято другим клиентом.
- Комментарий или объявление длиннее лимита.

### Почему кнопка «Хосты» не работает / раздел пустой?

- Не включён **Режим Multi-Node**.

### Почему нода offline?

- Контейнер воркера не запущен на сервере.
- Неверный `SECRET_KEY` или `PANEL_URL` при установке.
- Панель не достучится до порта API ноды (файрвол).

### Почему после смены пароля отключилась 2FA?

- Это штатное поведение: при смене учётных данных 2FA сбрасывается. Включите заново в **Безопасность**.

### Почему не могу изменить порт панели в настройках?

- Порт, домен и пути SSL задаются при установке (переменные окружения). В UI они только для просмотра.

### Почему отчёт / статистика пустая?

- Нет клиентов или никто не подключался.
- Фильтры слишком узкие — нажмите **Сбросить фильтры**.
- Нода offline — трафик не собирается.

### Почему в интерфейсе часть надписей на английском?

- Для некоторых новых элементов перевод в `ru.json` ещё не добавлен — показывается запасной английский текст.

### Почему нельзя добавить второго администратора?

- В текущей версии предусмотрена **одна** учётная запись администратора.

# 9. Советы пользователю

1. **Сразу смените пароль** `admin`/`admin` после установки.
2. **Включите 2FA** для учётной записи администратора.
3. **Именуйте подключения понятно** — `VLESS-CF-443-EU`, а не `inbound1`.
4. **Один протокол — одно подключение**; не смешивайте разные транспорты в одном inbound.
5. **Перед выдачей клиенту** проверьте подписку в том же приложении, что у пользователя.
6. **Multi-Node:** сначала ноды и подключения, потом хосты, потом клиенты.
7. **Хосты для CDN** — настраивайте Force TLS/none согласно схеме reverse proxy.
8. **Группы** — используйте для тарифов (базовый/премиум) и массовых продлений.
9. **Резервная копия** — экспортируйте БД перед крупными изменениями (Обзор → Резервная копия).
10. **Не раздавайте доступ к панели** — один админ, сильный пароль, HTTPS.
11. **HWID** — предупреждайте пользователей: только Happ/v2rayTun; при смене телефона может потребоваться очистка HWID.
12. **Журнал** — при «Сбой» смотрите Обзор → Журнал для деталей.

# 10. Термины

| Термин | Определение |
|--------|-------------|
| **Панель** | Веб-интерфейс SharX для администратора |
| **Администратор** | Пользователь, входящий в панель (не путать с клиентом) |

| **Нода** | Удалённый сервер-воркер с Xray в режиме Multi-Node |

| **Sub ID** | Уникальный идентификатор подписки клиента (16 символов) |
| **UUID** | Идентификатор клиента в протоколе (vless/vmess) |
| **Multi-Node** | Режим: Xray на панели не работает, трафик на нодах |
| **HWID** | Идентификатор устройства для ограничения числа устройств |
| **2FA** | Двухфакторная аутентификация при входе в панель |
| **Sidecar** | Дополнительный сервис на ноде (Telemt, AmneziaWG) |
| **Публичная страница подписки** | Веб-страница для клиента: `/panel/sub/?id=...` |
| **Группа** | Набор клиентов для массовых операций |
| **Provider ID** | Идентификатор провайдера для приложения Happ |
