# 13. Пакеты

[← Настройки](./12-nastrojki.md) | [Оглавление](./README.md) | [Балансировщики →](./14-balansirovshchiki.md)

## Что такое пакет

**Пакет (Bundle)** — упорядоченный набор [хостов](./06-hosty.md). Клиент, состоящий в пакете, получает эти хосты в **подписке** и **доступ к инбаундам** этих хостов.

С версии **2.0** это единственный способ выдать клиенту доступ. Раньше (до 2.0) в карточке клиента выбирали список inbound'ов; теперь он заменён пакетами.

```
Инбаунд ──► Хост (адрес + порт одного инбаунда) ──► Пакет (упорядоченный набор хостов) ──► Клиент
```

Раздел **Пакеты** (`/panel/bundles/`) есть в боковом меню всегда.

## Правила

| Правило | Что это значит |
|---------|----------------|
| **Порядок** | Порядок хостов в пакете = порядок записей в подписке. Пакеты клиента идут в порядке назначения. |
| **Доступ** | Доступ клиента = объединение инбаундов **всех хостов всех включённых пакетов**. Считается по каждому хосту пакета, даже скрытому или отключённому. |
| **Скрыть хост** | Значок «Скрыть из подписки»: запись не показывается в подписке, но доступ к инбаунду **остаётся**. |
| **Включён / выключен** | Переключатель «Включён» у пакета или хоста влияет **только на выдачу в подписке**, но не на доступ. Чтобы отобрать доступ, уберите хост из пакета или клиента из пакета. |
| **Автодобавление новых нод** | Опция «Добавлять новые ноды и пулы балансировщиков этих инбаундов автоматически» (`followPlacements`): когда у инбаунда, уже входящего в пакет, появляется новая нода или пул, соответствующий хост сам добавляется в **конец** пакета. |
| **Автопакет** | Служебный пакет (метка «авто»). Его создаёт слой совместимости API, когда интеграция передаёт `inboundIds`. Вручную им не управляют. |
| **Дубли** | В подписке хосты не дублируются (первое вхождение побеждает). Пропускаются скрытые, отключённые, хосты отключённых инбаундов и неподдерживаемые протоколы. |

## Создание пакета (пошагово)

1. **Пакеты** → **Создать пакет**.
2. Вкладка **Хосты**: введите **Название** и **Описание**, затем **Добавить хост…** и выберите нужные хосты (для каждого показан вид: «Нода», «Балансировщик», «Панель», «Адрес»).
3. Порядок задайте кнопками **Выше** / **Ниже**. Значок «Скрыть из подписки» / «Показывать в подписке» переключает видимость хоста, корзина убирает хост из пакета.
4. Вкладка **Параметры**: переключатель **Включён** и опция автодобавления новых нод и пулов.
5. Вкладка **Клиенты** доступна **после первого сохранения** («Сначала сохраните пакет, затем добавляйте клиентов»): **Найти клиента…**, добавление и удаление. Изменения применяются сразу: клиент получает или теряет доступ на нодах.
6. Перед сохранением пакета с клиентами панель показывает, сколько клиентов затронуто; после сохранения — «Доступ изменён у клиентов: N».

## Назначение пакетов

| Кому | Как |
|------|-----|
| Одному клиенту | В форме клиента блок **Пакеты**: прокручиваемый список, клик выбирает или снимает пакет. Под ним показан список «Инбаунды клиента» (итоговый доступ). |
| Нескольким клиентам | Вкладка **Клиенты** внутри пакета. |
| Группе | В форме группы секция **Пакеты**; **Сохранить** задаёт эти пакеты каждому клиенту группы ([Группы](./08-gruppy.md)). Личный доступ клиентов, выданный через API (`inboundIds`), сохраняется. |
| Через API | `bundleIds` в `POST /panel/client/add\|update`; `POST /panel/bundle/members/add`; `POST /panel/group/{id}/bulk/assignBundles`. |

Старый вызов с `inboundIds` продолжает работать: панель помещает клиента в **автопакет** для этого упорядоченного набора инбаундов. Именованные пакеты клиента при этом не меняются; `inboundIds: null` — «оставить как есть».

## Удаление

Удаление пакета: клиенты теряют доступ, который давал **только** этот пакет (панель показывает их число). Хосты, инбаунды и ноды не удаляются.

## Ограничения

- Массового действия «добавить выбранных клиентов в пакет» на странице **Клиенты** пока нет: используйте вкладку **Клиенты** пакета, форму клиента, группу или API.
- Шаблонов подписки на уровень пакета и «пакетов по умолчанию для группы» пока нет.
- Отката на схему без пакетов из панели нет (только восстановление из резервной копии БД).
- Хост принадлежит **одному** инбаунду: для двух инбаундов нужны два хоста.

## Пример

Пакет «Европа»: хосты `DE-1 (vless)`, `FI-1 (vless)`, `lb.example.com` (хост балансировщика). Клиент в пакете получит в подписке три записи в этом порядке. Если скрыть `FI-1`, запись пропадёт из подписки, а доступ к инбаунду на FI-1 останется.

Сценарий «выдать новому клиенту доступ»: **Клиенты → Добавить клиента** → в блоке **Пакеты** выберите «Европа» → **Сохранить**.

## Как проходит конвертация при обновлении до 2.0

При первом старте панели 2.0 данные 1.x **автоматически** переводятся на пакеты. Схема пакетов строится **рядом** со старой и проверяется, прежде чем стать активной:

1. Создаются резервные копии таблиц (`client_inbound_mappings_pre_bundles`, `hosts_pre_bundles`, `host_inbound_mappings_pre_bundles`, `inbound_node_mappings_pre_bundles`).
2. По каждой привязке инбаунда к ноде создаётся хост «Нода», по каждому прежнему хосту и каждому его инбаунду — адресный хост, по каждому пулу балансировщика — хост «Балансировщик». Режимы «заменить / вперёд / назад» превращаются в порядок хостов.
3. Клиенты группируются по **точному упорядоченному списку** своих инбаундов; на каждый различный список создаётся один пакет.
4. **Проверка для всех клиентов**: доступ совпадает, подписка совпадает побайтно (случайные параметры Reality `sni`, `sid`, `spx` при сравнении маскируются), строки `client_inbound_mappings` и клиентские списки нод не изменились, каждый клиент состоит в пакете.
5. Только при полном совпадении включается схема пакетов. При **любом** расхождении панель остаётся на старой схеме, клиенты ничего не теряют.

Откат из панели не предусмотрен. Старые таблицы конвертация не меняет; при необходимости состояние восстанавливают из резервной копии БД, сделанной **перед обновлением**.

### Как проверить результат

1. Откройте **Пакеты**. Баннер сверху показывает статус: «Конвертировано автоматически: клиентов N, пакетов M, подписок проверено и совпало K» или причину, по которой схема не переключилась.
2. Или через API: `GET /panel/bundle/state`. Ответ содержит `enabled` и `report` (`status`: `converted` или `failed`; при ошибке в `report.mismatches` указано, где именно подписка не совпала: `client`, `check`, `detail`).
3. Если конвертация не переключила схему (`enabled: false`), панель продолжает работать на старой схеме. После исправления причины нажмите **Конвертировать сейчас** (`POST /panel/bundle/convert`). Неудачная конвертация не повторяется на каждом старте, только на новой версии панели или по вашему запросу.
