# 15. Безопасность

[← Балансировщики](./14-balansirovshchiki.md) | [Оглавление](./README.md)

Чек-лист для администраторов, которые запускают SharX в продакшене.

## База данных

- Не публикуйте PostgreSQL (порт 5432) на внешнем интерфейсе. В `docker-compose.yml` по умолчанию порт привязан к `127.0.0.1`, оставьте так.
- Замените пароль базы из `.env` до первого запуска на длинное случайное значение.
- Если панель и база на разных серверах, используйте частную сеть или TLS.

## Доступ к панели

- Открывайте панель только по HTTPS и держите её за обратным прокси, который контролируете вы. Не выставляйте порт панели наружу рядом с прокси: заголовкам с IP клиента (`X-Forwarded-For`) можно доверять, только когда их ставит ваш прокси.
- Включите двухфакторную аутентификацию для каждого администратора (Настройки → Безопасность) и используйте уникальные пароли.
- Регулярно смотрите активные сеансы (Настройки → Безопасность → Сеансы) и завершайте незнакомые.
- Выдавайте админские аккаунты только тем, кому они нужны: администратор может импортировать и экспортировать базу, менять конфигурацию Xray и управлять нодами.

## API-токены

- Относитесь к токенам как к паролям: один токен на интеграцию, храните в менеджере секретов, удаляйте неиспользуемые.
- Периодически перевыпускайте токены. Токен действует, пока вы его не удалите.

## Ноды

- Ограничьте эндпоинт здоровья ноды (`/health`) и метрики Prometheus сетью мониторинга через файрвол или правила прокси. Они раскрывают версии, аптайм и состояние сайдкаров.
- При установке ноды по SSH сверьте отпечаток сервера сами, прежде чем вводить учётные данные.
- Если нода или хост установки могли быть скомпрометированы, перевыпустите секрет сопряжения и заново сопрягите ноды.

## Обновления и Docker

- Обновляйте панель, ноды и балансировщики: через диалог версии в панели или подтянув свежие образы.
- У Watchtower есть доступ к сокету Docker, а это равно root на хосте. Держите его HTTP API на `127.0.0.1` и задайте надёжный `WATCHTOWER_HTTP_API_TOKEN`.
- Скачивайте гео-файлы и шаблоны только из надёжных источников.

## Резервные копии

- Экспорт базы содержит хеши паролей, ID подписок и секреты. Храните бэкапы в зашифрованном виде и ограничьте доступ.
- Убедитесь, что в контейнере панели есть `pg_dump` (в официальном образе он есть), чтобы экспорт был полным. Восстанавливайте только файлы, созданные панелью.
- После восстановления проверьте, что панель запускается и миграции завершаются без ошибок.
