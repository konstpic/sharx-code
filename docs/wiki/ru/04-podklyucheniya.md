# 4. Подключения (Inbounds)

[← Веб-интерфейс](./03-veb-interfejs.md) | [Оглавление](./README.md) | [Ноды →](./05-nody.md)

## Что такое inbound

**Inbound (подключение)** — слушатель на сервере, который принимает входящие соединения от клиентских приложений. Каждый inbound определяет:

- **протокол** (VLESS, VMess, Trojan и др.);
- **порт** прослушивания;
- **транспорт** (TCP, WebSocket, gRPC, REALITY и т.д.);
- **TLS / REALITY** — шифрование и маскировка;
- **параметры аутентификации** (UUID, пароль, flow).

Учётные данные конечных пользователей (UUID, пароли) хранятся в **клиентах**, а не в inbound'е. Один inbound обслуживает множество клиентов.

### Цепочка: inbound → нода → хост → клиент

```
Inbound (протокол, порт, TLS)
    ↓ назначается на
Нода (где реально слушает Xray)
    ↓ при необходимости
Хост (какой домен видит клиент в подписке)
    ↓ назначается
Клиент (UUID, лимиты, subId)
```

## Список подключений

Страница **Подключения** (`/panel/inbounds/`) показывает таблицу всех inbound'ов:

| Колонка | Описание |
|---------|----------|
| ID | Идентификатор |
| Примечание | Имя подключения |
| Протокол | VLESS, VMess и т.д. |
| Порт | Порт прослушивания |
| Трафик ↑/↓ | Суммарный трафик |
| Клиенты | Количество привязанных клиентов |
| Состояние | Включён / выключен |

Доступны фильтры, сортировка и переключение между табличным и плиточным видом.

## Создание подключения

Нажмите **Добавить подключение** — откроется пошаговый мастер.

### Шаг 1. Основные параметры

| Поле | Описание |
|------|----------|
| **Примечание** | Имя подключения (для удобства) |
| **Протокол** | Выбор из списка (см. ниже) |
| **Порт** | Порт прослушивания (генерируется случайно, можно изменить) |
| **Слушать** | IP-адрес (`0.0.0.0` — все интерфейсы) |
| **Включить** | Активность подключения |
| **Сброс трафика** | Периодический сброс счётчика: никогда / час / день / неделя / месяц |

### Шаг 2. Транспорт (Stream / Transport)

Настройки зависят от протокола. Для Xray-протоколов:

| Параметр | Варианты |
|----------|----------|
| **Сеть (Network)** | `tcp`, `ws`, `grpc`, `quic`, `xhttp`, `httpupgrade`, `kcp`, `h2` |
| **Безопасность (Security)** | `none`, `tls`, `reality` |

#### TCP

Базовый транспорт. Дополнительно: HTTP-маскировка (header type).

#### WebSocket (ws)

| Поле | Описание |
|------|----------|
| Path | Путь WebSocket (например, `/ws`) |
| Host | Заголовок Host |

#### gRPC

| Поле | Описание |
|------|----------|
| Service Name | Имя gRPC-сервиса |
| Multi Mode | Режим мультиплексирования |

#### REALITY

| Поле | Описание |
|------|----------|
| Dest | Целевой адрес для маскировки (например, `www.google.com:443`) |
| Server Names | SNI-имена |
| Private Key / Public Key | Ключи REALITY |
| Short IDs | Короткие идентификаторы |

#### TLS

| Поле | Описание |
|------|----------|
| Сертификат | Путь к cert или Let's Encrypt |
| SNI | Server Name Indication |
| ALPN | `h2`, `http/1.1` |
| Fingerprint | Отпечаток TLS (chrome, firefox и др.) |

> Параметры TLS и REALITY должны совпадать с тем, что разрешено вашим CDN или файрволом.

### Шаг 3. Аутентификация

Зависит от протокола:

| Протокол | Параметры |
|----------|-----------|
| **VLESS** | Flow (xtls-rprx-vision и др.), Decryption |
| **VMess** | Security (auto, aes-128-gcm, chacha20-poly1305, none) |
| **Trojan** | Пароль (задаётся на уровне клиента) |
| **Shadowsocks** | Метод шифрования (aes-256-gcm, chacha20-poly1305, 2022-blake3 и др.) |
| **Hysteria 2** | Obfuscation (salamander), пароль |
| **WireGuard** | Secret Key, Peers |
| **AmneziaWG** | Параметры sidecar (Jc, Jmin, Jmax, S1, S2, H и др.) |
| **Telemt (MTProto)** | Параметры MTProto-прокси (без Xray streamSettings) |

### Шаг 4. Sniffing

Включение определения протокола входящего трафика:

- HTTP, TLS, QUIC, FakedNS
- Route Only / Metadata Only

### Шаг 5. Ноды (только Multi-Node)

При включённом режиме Multi-Node:

1. Выберите **ноды**, на которых будет работать это подключение.
2. Для каждой привязки настройте:
   - **Включить в подписку** — показывать ли в подписке клиента;
   - **Опубликованный адрес/порт** — что увидит клиент (может отличаться от адреса ноды);
   - **Суффикс примечания** — дополнение к имени в подписке.

## Протоколы — краткий справочник

### VLESS

Современный протокол Xray. Поддерживает XTLS Vision, REALITY. Рекомендуется для новых установок.

**Типичная связка:** VLESS + TCP + REALITY или VLESS + WS + TLS.

### VMess

Классический протокол V2Ray. Широкая поддержка клиентами.

**Типичная связка:** VMess + WS + TLS.

### Trojan

Маскируется под обычный HTTPS-трафик. Требует валидный TLS-сертификат.

### Shadowsocks

Лёгкий прокси-протокол. Поддерживает методы 2022-blake3.

### Mixed

SOCKS5 + HTTP-прокси на одном порту.

### Hysteria 2

UDP-протокол с высокой пропускной способностью. Поддерживает обфускацию salamander.

### WireGuard

VPN через WireGuard внутри Xray. Транспорт UDP, без TCP/WebSocket.

### AmneziaWG

Модифицированный WireGuard (sidecar Amnezia). Конфигурация выдаётся в формате `.conf` для приложения AmneziaVPN.

### Telemt (MTProto)

Прокси для Telegram. Работает как sidecar, не использует Xray streamSettings.

## Пошаговые примеры настройки

### Пример 1: VLESS + REALITY (рекомендуется)

| Шаг | Параметр | Значение |
|-----|----------|----------|
| 1. Основные | Протокол | VLESS |
| | Порт | `443` |
| | Примечание | `VLESS-REALITY` |
| 2. Транспорт | Network | tcp |
| | Security | reality |
| | Dest | `www.microsoft.com:443` |
| | Server Names | `www.microsoft.com` |
| | Short IDs | сгенерировать |
| 3. Аутентификация | Flow | `xtls-rprx-vision` (опционально) |
| 5. Ноды | Выбрать ноду | DE-Server |

Создайте клиента с этим inbound → подписка содержит строку с REALITY-параметрами.

### Пример 2: VLESS + WebSocket + TLS (CDN Cloudflare)

| Шаг | Параметр | Значение |
|-----|----------|----------|
| 1. Основные | Протокол | VLESS |
| | Порт на ноде | `10000` (локальный) |
| 2. Транспорт | Network | ws |
| | Path | `/ws` |
| | Security | none (TLS на CDN) |
| 5. Ноды | Нода | EU-Server |

Затем создайте **хост** → [Хосты](./06-hosty.md):

- Адрес: `cdn.example.com`, порт `443`, режим **replace**
- HTTP Host: `cdn.example.com`, Path: `/ws`, Force TLS: **tls**

### Пример 3: Shadowsocks 2022

| Шаг | Параметр | Значение |
|-----|----------|----------|
| 1. Основные | Протокол | Shadowsocks |
| | Порт | `8388` |
| 3. Аутентификация | Метод | `2022-blake3-aes-256-gcm` |

Пароль клиента генерируется на уровне клиента.

### Пример 4: AmneziaWG (sidecar)

| Шаг | Параметр | Значение |
|-----|----------|----------|
| 1. Основные | Протокол | AmneziaWG |
| 3. Аутентификация | Jc, Jmin, Jmax… | по документации Amnezia |
| 5. Ноды | Нода с AWG sidecar | выбрать |

Клиент получит `.conf` для импорта в AmneziaVPN.

Из меню строки inbound'а:

| Действие | Описание |
|----------|----------|
| **Редактировать** | Изменить параметры |
| **Клонировать** | Скопировать настройки (порт и IP задаются заново) |
| **Сбросить трафик** | Обнулить счётчик |
| **Клиенты** | Список клиентов на этом inbound |
| **Экспорт ссылок** | Ссылки для клиентов |
| **Удалить** | Удалить подключение |

## Single-node vs Multi-Node

| | Single-node | Multi-Node |
|---|-------------|------------|
| Где работает Xray | На сервере панели | На удалённых нодах |
| Шаг «Ноды» | Скрыт | Обязателен |
| Адрес в подписке | Адрес панели | Адрес ноды (или хоста) |

## Рекомендации

1. **Один протокол — один inbound** для разных портов или транспортов.
2. **REALITY** — для обхода блокировок без собственного домена.
3. **TLS + WS** — для работы через CDN (Cloudflare и др.).
4. **Согласуйте параметры** с возможностями клиентского приложения.
5. При большом числе inbound'ов используйте **фильтры и сортировку**.
