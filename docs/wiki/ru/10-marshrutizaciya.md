# 10. Маршрутизация

[← Страница подписки](./09-stranica-podpiski.md) | [Оглавление](./README.md) | [HWID и лимиты →](./11-hwid-i-limity.md)

В SharX существует **несколько независимых видов маршрутизации**. Важно не путать их:

| Вид | Где настраивается | Что делает |
|-----|-------------------|------------|
| **Хосты** | [Хосты](./06-hosty.md) | Подмена адресов и TLS в подписке |
| **Маршрутизация клиента** | Настройки → Подписка → Маршрутизация клиента | Правила для Happ / sing-box на устройстве |
| **Маршрутизация Xray** | Xray → Шаблон / Профили ядра | Серверные правила на ноде |
| **JSON-шаблоны** | Настройки → Подписка → JSON-шаблоны | Доп. правила в JSON-подписке |
| **Блокировка IP (лимит)** | Автоматически при IP limit | Hot-push блокировки на ноды |

> Подмена адресов в подписке (CDN, домены) — это **[Хосты](./06-hosty.md)**, не этот раздел.

## Маршрутизация клиента (Happ)

**Настройки → Подписка → Маршрутизация клиента**

Профили маршрутизации в формате, совместимом с **Happ** и аналогичными клиентами. Доставляются через HTTP-заголовки подписки:

| Заголовок | Описание |
|-----------|----------|
| `Routing` | Deeplink: `happ://routing/add/{base64(JSON)}` |
| `Routing-Enable` | `1` — включить маршрутизацию |

### Когда использовать

- Разделить трафик: российские сайты — DIRECT, остальное — PROXY.
- Заблокировать рекламу (geosite:category-ads-all → BLOCK).
- Настроить DNS (локальный / через прокси).
- Выдать единый профиль маршрутизации всем клиентам Happ.

### Параметры профиля

| Параметр | Описание |
|----------|----------|
| **Глобальный прокси** | Весь трафик через прокси |
| **Порядок маршрутов** | Последовательность применения правил |
| **Стратегия доменов** | AsIs, IPIfNonMatch, IPOnDemand |

### Правила

Для каждого правила задаётся действие и списки:

| Действие | Описание |
|----------|----------|
| **DIRECT** | Прямое соединение |
| **PROXY** | Через прокси |
| **BLOCK** | Блокировка |

Списки:

- **Сайты** (домены, geosite: `geosite:ru`, `geosite:google`);
- **IP** (CIDR, geoip: `geoip:private`).

### DNS

| Вкладка | Описание |
|---------|----------|
| **Удалённый DNS** | DNS через прокси (1.1.1.1, 8.8.8.8) |
| **Локальный DNS** | DNS напрямую |
| **DNS hosts** | Статические записи (`example.com → 1.2.3.4`) |
| **GeoIP / Geosite URL** | Ссылки на списки |

### Deeplink-пресеты

| Пресет | Префикс |
|--------|---------|
| Happ | `happ://routing/add/` |
| Incy | `incy://routing/add/` |
| SharX | Собственный формат |
| Custom | Произвольный префикс |

### Пример: Россия DIRECT, остальное PROXY

```
Правило 1: geosite:ru → DIRECT
Правило 2: geoip:ru → DIRECT
Правило 3: 0.0.0.0/0 → PROXY
```

Клиент Happ при обновлении подписки получит заголовок `Routing` с deeplink на этот профиль.

## Маршрутизация Xray (серверная)

**Xray → Шаблон** (`/panel/xray/`) или **Профили ядра** (`/panel/xray-core-config-profiles/`)

Правила маршрутизации на стороне **сервера** (Xray core). Определяют, куда направлять трафик **после** принятия на inbound.

### Когда использовать

- Развести трафик разных inbound'ов на разные outbound'ы.
- Заблокировать BitTorrent на сервере.
- Направить трафик через цепочку прокси (double-hop).
- Настроить балансировку между несколькими exit-нодами.

### Конструктор правил

Каждое правило содержит:

| Поле | Описание |
|------|----------|
| **Тип** | field / logical |
| **Домен** | Список доменов |
| **IP** | CIDR |
| **Порт** | Диапазон портов |
| **Inbound Tag** | Тег входящего подключения |
| **Outbound Tag** | Тег исходящего (freedom, proxy, block) |
| **Balancer Tag** | Балансировщик |

Правила применяются **сверху вниз** — первое совпадение побеждает.

### Outbound'ы

Страница **Outbounds** (`/panel/outbounds/`):

| Протокол | Назначение |
|----------|------------|
| `freedom` | Прямой выход в интернет |
| `blackhole` | Отбрасывание трафика |
| `socks` / `http` | Через другой прокси |
| `vless`, `vmess`, `trojan`… | Цепочка через другой сервер |

### Профили ядра

В multi-node каждой ноде можно назначить **профиль конфигурации ядра** — отдельный набор routing/outbound/dns правил. Например: EU-ноды с одним профилем, US-ноды с другим.

## JSON-шаблоны маршрутизации

**Настройки → Подписка → JSON-шаблоны → Правила**

Дополнительные правила маршрутизации, которые **добавляются в начало** секции routing JSON-подписки (для sing-box, Xray JSON формата).

Полезно, когда клиентское приложение читает routing из тела подписки, а не из заголовков Happ.

## Автоматическая блокировка IP

При включённом **лимите одновременных IP** (см. [HWID и лимиты](./11-hwid-i-limity.md#лимит-одновременных-ip)) панель автоматически добавляет правила маршрутизации на ноды для блокировки «лишних» IP-адресов.

| Режим | Действие |
|-------|----------|
| **Drop** | Разрыв активных соединений |
| **Block** | Запрет подписки/маршрутизации для IP |
| **Drop + Block** | Оба действия |

## Схема: что куда настраивать

```
Подписка клиента
├── Адрес сервера      → Хосты (домен) + Ноды (IP)
├── TLS в ссылке       → Inbound или Хост (override)
├── Routing на телефоне → Client routing (Happ)
└── JSON routing       → JSON-шаблоны

Трафик на сервере
└── Куда отправить     → Xray routing + Outbounds
```

---

## Рекомендации

1. **Хосты** — для CDN и доменов; см. [отдельный раздел](./06-hosty.md).
2. **Client routing** — для Happ-пользователей (split tunneling, блокировки).
3. **Xray routing** — для серверной политики (exit, block, chain).
4. Не дублируйте одни и те же правила в трёх местах — выберите уровень под задачу.
