## Что такое SharX

**SharX** — современная платформа управления **Xray-core** с поддержкой распределённой архитектуры (несколько серверов-воркеров), визуальным конструктором страницы подписки и расширенным контролем доступа клиентов.

Панель позволяет:

- создавать и управлять **подключениями** (inbound) с разными протоколами и транспортами;
- вести учёт **клиентов** (конечных пользователей) с лимитами трафика, сроками и ограничениями устройств;
- раздавать конфигурации через **подписку** — в формате, понятном конкретному клиентскому приложению;
- масштабировать инфраструктуру, добавляя **ноды** (worker-серверы) под управлением одной панели;
- настраивать **публичную страницу подписки** с брендингом, инструкциями и кнопками импорта.

### Режимы работы

| Режим | Описание |
|-------|----------|
| **Одиночный (single-node)** | Xray запускается на том же сервере, что и панель. Подходит для небольших установок. |
| **Multi-Node** | Xray на панели **не работает**; конфигурации отправляются на удалённые **ноды**. Трафик обрабатывается на воркерах. |

Режим Multi-Node включается в **Настройки → Общие → Режим Multi-Node**.

## Основные сущности

### Подключение (Inbound)

Слушатель на сервере: протокол (VLESS, VMess, Trojan и др.), порт, транспорт (TCP, WebSocket, gRPC, REALITY и т.д.), параметры TLS. Один inbound может обслуживать множество клиентов.

### Клиент (Client)

Учётная запись конечного пользователя. Содержит UUID/пароль, привязку к inbound'ам, лимиты, срок действия, идентификатор подписки (`subId`). **Не путать с администратором панели.**

### Нода (Node)

Удалённый сервер с воркером SharX и Xray. Панель через защищённый API (mTLS + JWT) отправляет конфигурацию, проверяет состояние и собирает статистику.

### Группа (Group)

Логическое объединение клиентов для удобства фильтрации и массовых операций (смена лимитов, назначение inbound'ов).

### Хост (Host)

Публичное имя или CDN-адрес в подписке. Подробнее: [Хосты](./06-hosty.md).

### Подписка (Subscription)

HTTP-эндпоинт, по которому клиентское приложение получает список серверов. Формат ответа зависит от User-Agent (Happ, v2rayNG, Clash, sing-box, браузер и др.).

## Поддерживаемые протоколы

| Протокол | Тип | Назначение |
|----------|-----|------------|
| **VLESS** | Xray | Основной протокол с поддержкой XTLS, REALITY |
| **VMess** | Xray | Классический протокол V2Ray |
| **Trojan** | Xray | Маскировка под HTTPS-трафик |
| **Shadowsocks** | Xray | SS с различными методами шифрования |
| **Mixed** | Xray | SOCKS + HTTP на одном порту |
| **Hysteria 2** | Xray | UDP-протокол с обфускацией |
| **WireGuard** | Xray | VPN через WireGuard |
| **AmneziaWG** | Sidecar | Модифицированный WireGuard (Amnezia) |
| **Telemt (MTProto)** | Sidecar | Прокси для Telegram |

## Порты по умолчанию

| Сервис | Порт | Назначение |
|--------|------|------------|
| Веб-панель | **2053** | Административный интерфейс |
| Подписки | **2096** | Эндпоинт подписки для клиентских приложений |
| PostgreSQL | **5432** | База данных (внутренний) |
| HTTP (SSL) | **80** | Получение Let's Encrypt сертификатов |

## Технологический стек

- **Панель (UI):** Next.js, React, TypeScript
- **Бэкенд:** Go (Gin), GORM, PostgreSQL
- **Прокси-ядро:** Xray-core
- **Развёртывание:** Docker, Docker Compose
- **Обновления:** Watchtower (в составе compose)
