## Release v1.7.26

**Release Date:** September 19, 2026

Релиз **v1.7.26** относительно **v1.7.25**: надёжный механизм обновления панели и нод (серверное задание вместо оркестрации из браузера) и исправление счётчика трафика Telemt после обновления до Telemt 3.5.x.

**Миграция БД:** нет (состояние задания хранится в таблице настроек).

> ⚠️ **Важно про само обновление на v1.7.26.** Новый механизм обновления заработает **только начиная со следующего обновления**. Обновление *до* v1.7.26 выполняет интерфейс уже установленной версии (v1.7.25) со старой логикой, поэтому в этот раз окно «Обновление контейнеров» ещё может показать «Network Error» (особенно если нода стоит на одном сервере с панелью), хотя обновление на самом деле пройдёт. Проверьте версии панели и нод после обновления. Со следующего обновления процесс идёт через серверное задание и такой ошибки не даёт.

---

### Fix: ложный «Network Error» при обновлении контейнеров, хотя обновление прошло

**Root cause:** обновление вёл браузер: он по очереди вызывал панель, а та — Watchtower на нодах. Если нода стоит на одном сервере с панелью, у них общий Watchtower: вызов обновления для такой ноды заставляет Watchtower пересоздать и панель (`Scanned=2 Updated=2`). Панель перезапускается посреди процесса, а все запросы браузера, включая уже успешно обновлённые ноды, обрываются — интерфейс красит всё в «Network Error». Заодно нарушался порядок «сначала ноды, потом панель».

**Fix:** обновление теперь серверное задание.

- Браузер только запускает задание и опрашивает его состояние; при перезапуске панели опрос просто переподключается («панель перезапускается — переподключаемся, ничего делать не нужно»).
- Состояние задания сохраняется после каждого изменения; после перезапуска панели задание **автоматически продолжается** и доводится до конца.
- Результат шага определяется по фактам, а не по обрыву соединения: версия ноды изменилась, нода перезапускалась, либо нода осталась на той же версии и в течение времени ожидания не перезапускалась — тогда «Уже актуальна». Нода, которая осталась на версии старее остальных, помечается ошибкой с понятной причиной; жёсткий отказ апдейтера (например, неверная настройка Watchtower) виден сразу.
- Порядок гарантируется: сначала удалённые ноды (параллельно), потом ноды на одном хосте с панелью (по одной), в конце сама панель. Совпадение хоста определяется по адресу ноды и сетевым интерфейсам сервера.
- В интерфейсе для каждой ноды видно `версия до → версия после` и статус (обновлена / уже актуальна / ошибка с причиной); по завершении — кнопка «Перезагрузить страницу», а после обновления панели страница перезагружается сама.
- Старые эндпоинты обновления сохранены.

### Fix: счётчик трафика Telemt («получено» оставалось 0)

**Root cause:** Telemt 3.5.x переименовал метрики в `telemt_user_octets_from_client_total{user=…}` и `telemt_user_octets_to_client_total{user=…}` (добавился суффикс `_total`). Нода искала прежние имена без суффикса, не находила данных и молча переходила на суммарный `total_octets` из JSON API, у которого нет разделения на приём и отдачу — весь трафик попадал в «отдачу», а «получено» (Down) оставалось 0.

**Fix:** парсер принимает оба варианта имён метрик. Если Prometheus-счётчики недоступны и нода вынуждена использовать суммарный счётчик, об этом теперь пишется предупреждение в лог (раньше — только на уровне debug).

**Важно:** этот фикс — в образе ноды. Ноды подхватят его при обновлении на v1.7.26.
