## Release v2.6.0

**Release Date:** October 8, 2026

Ролевая модель доступа: пользователи, роли, права на каждый раздел и действие, журнал аудита, персональная 2FA.

**Миграция БД:** да — `0064_rbac.sql` (роли, журнал аудита, поля пользователей) и `0065_user_two_factor.sql` (персональная 2FA). Обе совместимы с прежней версией: существующие пользователи становятся администраторами, общий секрет 2FA копируется каждому. Откат: вернуть прежнюю версию, таблицы и столбцы можно оставить (см. `docs/architecture/rbac.md`).
**Изменения API:** новые `/panel/rbac/*`, `setting/twoFactor/disable`, `api/server/logs/entity/audit/0`. Токены API работают как раньше и несут права владельца.
**Обновление:** только панель.

### Доступ

- Роли и пользователи (раздел «Доступ»): ~56 прав вида `ресурс:действие`, встроенная роль Administrator неизменяема, защита от эскалации прав и от удаления/отключения последнего администратора, мягкое удаление пользователей.
- Проверка на сервере в одном месте для каждого маршрута; маршрут без записи в таблице прав доступен только администраторам. Интерфейс скрывает недоступное и показывает формы только для чтения.
- Отключение пользователя или смена роли действуют со следующего запроса, открытые сессии закрываются.
- WebSocket, настройки, ключи и клиенты инбаундов, журналы нод и балансировщиков фильтруются по правам.

### 2FA

- TOTP теперь у каждого пользователя свой; включить и выключить (по коду) может любой. Администратор с `users:update` может сбросить 2FA нижестоящему пользователю. `x-ui setting -resetTwoFactor` сбрасывает 2FA у всех.

### Журнал аудита

- Тот же просмотрщик, что у журналов нод и панели: понятное описание действия и результата, фильтры, скачивание. Отказанные обращения к API записываются. Хранение — по настройке ротации логов («макс. возраст»), старые записи удаляются раз в час.
