## Release v1.7.32

**Release Date:** September 23, 2026

Релиз **v1.7.32** относительно **v1.7.30**: устранены две гонки за порт 443 между Telemt WEB и Xray на ноде, плюс дашборд панели переработан — убрана дублирующая карточка «Панель и ядра нод», раздел «Обслуживание» разбит на четыре полноценные карточки с показом реально установленной версии ядра.

**Миграция БД:** нет.

---

### Fix: Telemt WEB фронт мог занять порт, нужный Xray

Сообщение от пользователя: при переносе конфигурации Telemt WEB на боевой сервер Xray не смог стартовать на 443, потому что порт уже держал встроенный TLS-фронт ноды. Помогало только вручную остановить Telemt, запустить Xray, затем снова включить Telemt.

**Root cause — два независимых состояния гонки:**

1. **При применении конфига (`apply-config`) порядок был обратным.** Нода сперва пыталась (пере)запустить Xray и только потом обновляла сайдкары, включая фронт Telemt WEB. Если админ только что включил «External TLS terminator» (или выключил WEB-режим) — то есть фронт должен был отдать порт — эта отдача происходила **после** попытки Xray забиндиться, а не до. Xray закономерно получал `address already in use`.
2. **При старте (перезапуске) ноды фронт почти всегда успевал первым.** Xray запускается как отдельный процесс: `exec.Cmd.Start()` возвращает управление сразу после fork+exec, задолго до того как xray-core реально загрузит конфиг и выполнит bind на свои порты. Резервный TLS-фронт Telemt WEB — часть того же Go-процесса ноды, его `net.Listen()` выполняется почти мгновенно. Поэтому даже при «правильном» порядке кода в источнике фронт почти всегда физически побеждал в гонке за порт при холодном старте.

**Fix:**
- В обработчике `apply-config` на ноде сайдкары (включая фронт Telemt WEB) применяются **до** попытки Xray забиндиться, а не после — отдача порта фронтом гарантированно происходит раньше, чем Xray успеет попробовать его занять.
- При старте ноды резервный запуск фронта Telemt WEB из локального кэша теперь откладывается на несколько секунд — Xray успевает забиндить свои порты первым, прежде чем в дело вступит фронт.

**Не сделано в этом релизе** (по формулировке из исходного репорта): полноценный «арбитр портов» на каждый `apply` с self-healing при `EADDRINUSE` и индикатором владельца порта в UI ноды — это более крупная архитектурная задача, оценивается отдельно. Текущий фикс закрывает конкретный воспроизведённый сценарий (переключение чекбокса и холодный старт), но не защищает от абсолютно всех мыслимых порядков событий.

### Feature: дашборд панели переработан

Было: карточка «Панель и ядра нод» дублировала функциональность страницы «Ноды», а журнал логов, версия ядра и резервная копия были зажаты в одну карточку «Управление» без подписей.

Стало:
- Дублирующая карточка «Панель и ядра нод» убрана.
- Раздел «Обслуживание» разбит на четыре полноценные карточки: **Журнал** (живые логи панели/Xray/нод), **Версия ядра**, **Резервная копия** (экспорт/импорт БД, ссылка на JSON-конфиг), **Время работы системы**.
- Карточка «Версия ядра» теперь показывает не то, что панель видит на своём локальном хосте, а реально установленную/раскатанную версию — то, что зафиксировано в БД по каждой ноде (в multi-node режиме версия агрегируется по включённым нодам; если ноды разошлись по версии — рядом с бейджем появляется жёлтый индикатор рассинхрона).
- В модалке выбора версии ядра сейчас установленная версия выделяется жирным и помечается бейджем «Текущая».
- Исправлена обрезка текста версии ядра на карточке дашборда (версия могла визуально обрезаться `truncate`-стилем и быть не видна полностью).

Адаптивно на мобильных — карточки складываются в один столбец.
