## Release v1.7.16

**Release Date:** September 17, 2026

Патч **v1.7.16** относительно **v1.7.15**: по живой обратной связи с прод-панели — Xray не поднимался сам после обновления ноды («пришлось вручную нажать перезапуск»). Найдена и устранена конкретная причина.

**Миграция БД:** нет.

---

### Root cause

После выката v1.7.15 на реальной установке (панель + 3 воркера) подтверждено: Telemt CI-фикс и per-file reseed из v1.7.15 работают правильно — все ноды обновились до `worker_version=1.7.15` с корректным `telemt_version=3.5.7`. Но на одной ноде после пересоздания контейнера **Xray не стартовал сам** — по логам видно 3 неудачные попытки локального `Xray watchdog` (нечего грузить, `config.json` ещё нет), и только спустя ~2 минуты панель сама протолкнула конфиг.

В коде уже есть механизм именно для этого случая — `node/configpull` (`TryPullAndApply`/`StartBackgroundPull`): нода при старте сама проактивно запрашивает конфиг у панели, с ретраями. Но он не сработал ни разу (в логах нет ни одной строки `Config pull:`), потому что требует известный `panelUrl`, а тот берётся либо из env `PANEL_URL`, либо из файла `node-config.json`. Этот файл сохранялся в `/app/bin` — том же неперсистентном месте, что и бинарники ядер (см. v1.7.15). На нодах без volume под `/app/bin` файл стирался при каждом пересоздании контейнера вместе со всем остальным, и нода теряла единственный способ узнать, у кого спрашивать конфиг — замкнутый круг: активный self-pull требует сохранённый `panelUrl`, а `panelUrl` сохраняется только после того, как панель сама один раз push’нула конфиг.

### Fixes

- **`node-config.json` теперь живёт в `/app/data`** (`node/main.go`, `node/config/config.go`)
  - `/app/data` — единственный volume, персистентный на всех задеплоенных нодах без исключения (в отличие от `/app/bin`, который есть не у всех).
  - `panelUrl`/`nodeId` переживают пересоздание контейнера → активный self-pull (`configpull`) реально срабатывает при старте → Xray поднимается сам за секунды, без ожидания следующего цикла health-check панели и без ручного вмешательства.
