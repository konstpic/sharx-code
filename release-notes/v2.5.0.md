## Release v2.5.0

**Release Date:** October 6, 2026

Балансировщики: исправлена потеря UDP-сессий (AmneziaWG/WireGuard/Hysteria2) за nginx, добавлены журналы нод и балансировщиков, счётчики и диагностика.

**Миграция БД:** нет.
**Изменения API:** добавлены `GET /panel/api/server/logs/entity/:type/:id`, `POST /panel/balancer/log-level/:id`; агент: `GET /api/v1/logs`, `POST /api/v1/log-level`, поле `diag` в статусе.
**Обновление:** панель и агент балансировщика (образ `sharxbalancer`) нужно обновить вместе.

### Fix: UDP через балансировщик (nginx)

- Без `reuseport` один клиентский поток делился между всеми воркерами nginx; каждый воркер создавал свою сессию к ноде, и при round robin пакеты одного клиента уходили на **разные ноды** и с разных портов. Туннель (AmneziaWG/WireGuard/QUIC) жил рывками и деградировал под нагрузкой, хотя «соединение установлено». Воспроизведено: 20000 датаграмм одного клиента давали 10 сессий на 2 нодах; после исправления — 1 сессия, 1 нода.
- UDP-пулы теперь всегда `listen … udp reuseport` и `hash $remote_addr consistent` (липкость по IP клиента) независимо от выбранного алгоритма.
- Автовес: вес по пингу теперь из 5 грубых ступеней, и пересчёт пропускается для пула с одним участником. Раньше вес дрожал вместе с RTT (23→16→1), и HAProxy перезагружался каждые ~10 секунд.

### Fix: «зомби»-соединения через TCP-балансировщик

- Клиент или нода, пропавшие без FIN/RST (телефон вне зоны, обрыв маршрута), держали сессию до 1 часа вместе с сокетом на ноде (лимиты и «онлайн» на ноде считали их живыми). Воспроизведено: 1500 сессий оставались открытыми через 150 с на HAProxy и nginx.
- HAProxy: keepalive на обеих сторонах (60 с простоя, интервал 15 с, 4 пробы); мёртвая сторона отсекается за ~2 минуты, при исчезновении ноды закрывается и клиентская сторона. nginx: `so_keepalive=60s:15s:4` для клиентов, мёртвый клиент отсекается за ~2 минуты. Для исчезнувшей ноды nginx использует системный keepalive ядра (2 часа): агент пишет предупреждение, рекомендация `net.ipv4.tcp_keepalive_time=120` на сервере или движок HAProxy для TCP.

### Журналы

- **Единый просмотрщик логов** (в духе Grafana/Loki) для дашборда, нод и балансировщиков: гистограмма объёма по уровням, чипы уровней и компонентов, поиск по словам (`-слово` исключает), период, Live, раскрываемые строки с фильтрами по полям, поле `ключ=значение` отдельно от текста, скачивание `.log` / `.ndjson` / `.csv` по текущим фильтрам (до 100 000 строк).
- **Журнал панели на дашборде** показывает только действия самой панели; логи нод, xray и агентов остаются в журналах нод и балансировщиков (без дублей). Добавлены записи «inbound created/updated/deleted»; отладочные строки `[DEBUG-AGENT]` переведены в debug.
- **Журнал ноды наконец получает записи с нод**: пушер логов читал `nodeId` не из того файла, и при незаданном `NODE_ADDRESS` панель не могла опознать ноду. Время записей нод больше не смещается по часовому поясу; шум опроса статистики xray (`[api -> api]`) скрыт, строки доступа читаются как `accepted dest from=… route="in → out" email=…`.
- **Ноды → нода → Логи** и **Балансировщики → балансировщик → Логи**.
- Вывод процессов **AmneziaWG** и **Telemt** теперь попадает в журнал (раньше был виден только в контейнере), без цветовых кодов и баннеров, с уровнями из самих процессов; рутинный шум Telemt (рукопожатия, ротация idle-писателей) на уровне debug. Панель сохраняет компонент записей ноды.
- Журнал агента балансировщика: apply/reload, старт/падение движка, падение и возврат бэкендов с failover, закрытые соединения (DEBUG, с id соединения), дропы на интерфейсах и заполнение conntrack.
- Счётчики на карточке балансировщика: соединения, ошибки, таймауты, отказы бэкендов, failover, перезагрузки, conntrack, дропы NIC.
- Исправлена гонка в буфере логов (запись из нескольких горутин без блокировки).
