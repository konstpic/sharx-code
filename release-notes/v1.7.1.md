## Release v1.7.1

**Release Date:** July 3, 2026

Патч **v1.7.1** относительно **v1.7.0**: точечная синхронизация конфига на worker-ноды без лишних restart и без push на ноды, не затронутые изменением.

**Миграция БД:** нет.

---

### Bug Fixes

- **Multi-node: push только на затронутые ноды**
  - Изменение клиентов / inbound’ов больше не вызывает `RestartXray` на **всех** worker-нодах.
  - Новый путь: `SyncWorkerXrayForInboundsAsync` → `GetNodesForInbound` только для изменённых inbound’ов (`web/service/xray_worker_sync.go`, `web/service/client.go`, `web/controller/inbound.go`).

- **Ложные restart Xray на ноде при неизменённом конфиге**
  - `ApplyConfig` сравнивает конфиги через **канонический JSON** (`EqualCanonical`), а не побайтовое сравнение с недетерминированным порядком ключей (`xray/config_canonical.go`, `node/xray/manager.go`).

- **Единый builder settings для hot/cold sync**
  - `buildNodeWorkerConfigJSON` собирает `settings` через `BuildSettingsFromClientEntities` / `RebuildInboundSettingsForXray` — тот же путь, что и `update-inbound` API (`web/service/xray.go`).

- **Стабильный порядок clients/inbounds**
  - `GetClientsForInbound`: `ORDER BY sort_order, id`; inbounds сортируются по tag перед сборкой worker JSON.

### Operational Notes

- Полный push на **все** worker-ноды по-прежнему возможен при глобальных операциях (шаблон Xray, `SetToNeedRestart` из traffic job, ручной restart) — это ожидаемо.
- На таких push ноды с **неизменённым** конфигом должны логировать `compare result=unchanged, action=skip-restart`.
