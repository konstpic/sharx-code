## Release v1.7.31

**Release Date:** September 23, 2026

Релиз **v1.7.31** относительно **v1.7.30**: устранены две гонки за порт 443 между Telemt WEB и Xray на ноде (чекбокс «External TLS terminator» теперь действует немедленно; на холодном старте ноды фронт больше не перехватывает порт раньше Xray), плюс переработан раздел «Обслуживание» на дашборде панели.

**Миграция БД:** нет.

---

### Fix: Telemt WEB фронт мог занять порт, нужный Xray

Сообщение от пользователя: при переносе конфигурации Telemt WEB на боевой сервер Xray не смог стартовать на 443, потому что порт уже держал встроенный TLS-фронт ноды (`node-service`). Помогло только вручную остановить Telemt, запустить Xray, затем снова включить Telemt.

**Root cause — два независимых состояния гонки:**

1. **При применении конфига (`apply-config`) порядок был обратным.** Нода сперва пыталась (пере)запустить Xray и только потом обновляла сайдкары, включая фронт Telemt WEB. Если админ только что включил «External TLS terminator» (или выключил WEB-режим) — то есть фронт должен был отдать порт — эта отдача происходила **после** попытки Xray забиндиться, а не до. Xray закономерно получал `address already in use`.
2. **При старте (перезапуске) ноды фронт почти всегда успевал первым.** Xray запускается как отдельный процесс: `exec.Cmd.Start()` возвращает управление сразу после fork+exec, задолго до того как xray-core реально загрузит конфиг и выполнит bind на свои порты. Резервный TLS-фронт Telemt WEB — часть того же Go-процесса ноды, его `net.Listen()` выполняется практически мгновенно. Поэтому даже при «правильном» порядке кода в источнике фронт почти всегда физически побеждал в гонке за порт при холодном старте.

**Fix:**
- В обработчике `apply-config` на ноде сайдкары (включая фронт Telemt WEB) применяются **до** попытки Xray забиндиться, а не после — тогда отдача порта фронтом гарантированно происходит раньше, чем Xray успеет попробовать его занять.
- При старте ноды резервный запуск фронта Telemt WEB из локального кэша теперь откладывается на несколько секунд — Xray успевает забиндить свои порты первым, прежде чем в дело вступит фронт.

**Не сделано в этом релизе** (по формулировке из репорта): полноценный «арбитр портов» на каждый `apply` с self-healing при `EADDRINUSE` и индикатором владельца порта в UI ноды — это более крупная архитектурная задача, оценивается отдельно. Текущий фикс закрывает конкретный воспроизведённый сценарий (переключение чекбокса и холодный старт), но не защищает от абсолютно всех мыслимых порядков событий.

### Feature: дашборд — раздел «Обслуживание» переработан

Было: три мелкие иконки без подписей в углу карточки «Управление» — журнал логов, конфиг, бэкап приходилось угадывать по наведению. Стало: карточка «Обслуживание» с тремя крупными плитками (иконка + заголовок + краткое описание): **Журнал** (живые логи панели/Xray/нод), **Версия ядра** (сразу видны текущие версии Xray и Telemt), **Резервная копия** (экспорт/импорт БД). Быстрая ссылка на JSON-конфиг Xray вынесена под плитки отдельной строкой. Адаптивно на мобильных — плитки складываются в один столбец.
