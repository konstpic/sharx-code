## Release v1.7.22

**Release Date:** September 18, 2026

Релиз **v1.7.22** относительно **v1.7.21**: новая фича — автоматическая установка ноды по SSH прямо из мастера добавления ноды в панели.

**Миграция БД:** нет — учётные данные SSH нигде не сохраняются, ничего в схеме не менялось.

---

### Feature: автоматическая установка ноды по SSH

До этого релиза добавление ноды означало: скопировать `docker-compose.yml`, вручную зайти на сервер, развернуть контейнер, вернуться в панель и подтвердить. Теперь на первом шаге мастера есть переключатель **Вручную / Автоматически (SSH)** — при выборе автоматического режима панель сама подключается к серверу по SSH, проверяет/ставит Docker, разворачивает `docker-compose.yml` (тот же самый, что и в ручном режиме — общий панельный `SECRET_KEY`) и поднимает контейнеры.

- **Аутентификация:** пароль или приватный ключ (с опциональной passphrase). Хост-ключ сервера не проверяется (trust-on-first-connect — тот же принцип, что и `ssh -o StrictHostKeyChecking=no` при первом ручном подключении: админ сам только что ввёл этот IP).
- **Учётные данные никогда не сохраняются** — только в памяти на время одной установки, не пишутся в БД и не попадают в логи.
- **Порядок операций специально изменён относительно первого прототипа**: SSH-установка идёт **до** создания записи ноды в БД, потому что `node/add` синхронно проверяет доступность ноды и удаляет только что созданную запись при неудаче — что гарантированно происходило бы для ноды, которая ещё не развёрнута. Запись создаётся только после того, как нода реально поднялась и стала доступна — тогда штатная проверка проходит естественным образом.
- **Настраиваемый локальный порт апдейтера** (`Updater local port`, по умолчанию 8081) — найдено и исправлено живым тестированием: у одного из тестовых серверов порт 8081 был заранее занят посторонним сервисом (nginx), из-за чего `docker compose up` предсказуемо падал на конфликте портов. Теперь порт можно переопределить прямо в мастере.
- Прогресс установки — по шагам (подключение → проверка/установка Docker → запись compose → запуск контейнеров), с живым опросом статуса и явной ошибкой при сбое любого шага, вместо тихого зависания.

### Test plan

- [x] `go build ./...`, `go vet ./...`, `go test ./...` — всё зелёное.
- [x] Юнит-тесты: генерация compose (включая экранирование SECRET_KEY с кавычками и переопределение порта апдейтера), `shellQuote`, обрезка длинного вывода ошибки, порядок и валидация шагов установки.
- [x] Транспортные тесты SSH: поднят локальный in-process mock SSH-сервер (`golang.org/x/crypto/ssh`), реально протестированы `sshRunCombined` (захват вывода, ненулевой exit code) и `sshCommandOK` — не только компиляция, а рабочая логика поверх настоящего SSH-соединения.
- [x] `npx tsc --noEmit` (panel) — без ошибок в изменённых компонентах.
- [x] **Живой end-to-end тест на реальном сервере** (по прямому запросу): удалил ноду DE-1 из тестовой панели, полностью снёс её контейнеры на сервере, прогнал автоматическую установку через реальный API прод-версии кода (временно развёрнутой на тестовой панели локальной сборкой, в обход CI/Harbor) — SSH-подключение, проверка Docker (уже стоял, шаг install_docker корректно помечен skipped), запись compose, поднятие контейнеров. Живьём поймал и исправил реальный конфликт порта 8081, затем повторный прогон с `watchtowerPort=8089` прошёл полностью успешно. Нода зарегистрирована в панели, statuses: `online`, `xrayState: running` (26.6.1), `telemtState: running` (3.5.7), `workerVersion` совпадает с панелью.
- [x] Тестовая панель возвращена на официальный образ с Harbor после теста.
