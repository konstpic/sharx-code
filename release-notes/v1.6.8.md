## Release v1.6.8

**Release Date:** July 1, 2026

Патч **v1.6.8** относительно **v1.6.7**: исправления Shadowsocks при push в Xray, одношаговое обновление панели и worker-нод через Watchtower, новая модалка прогресса обновления.

**Миграция БД:** не требуется.

---

### Bug Fixes

- **Shadowsocks: `bad key` (SS2022) и `unsupported cipher method` (chacha/xchacha)** (`web/service/shadowsocks_method.go`, `web/service/inbound.go`, `web/service/xray.go`)
  - **Симптом:** Xray падал при старте — невалидный PSK у клиента SS2022 (не 32 байта в base64) или отсутствие `method` в `clients[]` у classic multi-user Shadowsocks.
  - **Фикс:** `EnsureShadowsocksUserPassword` нормализует/регенерирует ключи; при сборке конфига из `ClientEntity` и в `SanitizeShadowsocksInboundSettings` ключи и `method` приводятся к виду, ожидаемому Xray; `GetXrayConfig` и push на ноды пересобирают settings для Shadowsocks (как для WireGuard/AWG).

- **Обновление Docker: панель перезапускалась раньше нод** (`web/service/docker_update.go`, `web/controller/server.go`, `web/service/node.go`)
  - **Симптом:** после первого клика «Обновить» Watchtower пересоздавал панель → HTTP-обработчик обрывался → удалённые ноды обновлялись, но не получали push конфига; требовался ручной повторный клик / push.
  - **Фикс:** оркестрация: pre-push конфига → обновление worker-нод → ожидание online → post-push → **в конце** Watchtower панели. Таймаут кнопки увеличен до 5 минут.

### Features

- **Модалка прогресса обновления** (`panel/components/panel/DockerUpdateProgressModal.tsx`, `panel/components/panel/PanelHeaderAppMeta.tsx`)
  - Список целей: **панель сверху**, **ноды снизу** (multi-node).
  - Пошаговые статусы: push конфига → trigger на нодах → ожидание online → push после рестарта → обновление панели → перезагрузка UI.
  - Пошаговые API: `GET/POST …/api/server/updater/plan|workers/prep|workers/trigger|workers/finish|panel/trigger` (legacy `POST …/updater/trigger` сохранён).
  - **Hotfix:** health-check нод — `POST /panel/node/check/:id` (раньше ошибочный `/panel/api/node/check/:id` → 404 и ложный «Сбой» панели); текст ошибки trigger под нодой.

### Operational Notes

- Обновляется **панель (`sharx`)**; worker-ноды (`sharxnode`) — по желанию (логика оркестрации на стороне панели, ноды получают те же API).
- После деплоя: один клик «Запустить обновление» в multi-node должен обновить все ноды и панель без ручного push конфига.
- SS2022 / classic SS: при первом push после обновления невалидные пароли клиентов могут быть автоматически перегенерированы в БД — клиентам может понадобиться обновить подписку.

### Test plan

- [ ] SS2022 inbound: push конфига → Xray на ноде стартует без `bad key`
- [ ] Classic SS (chacha20-ietf-poly1305): multi-user → без `unsupported cipher method`
- [ ] Multi-node + Watchtower: один клик обновления → ноды online с конфигом, панель перезапускается последней
- [ ] Модалка: панель в статусе «Ожидание», ноды проходят «Обновление…» → «Готово»
- [ ] Single-node (без multi): обновляется только панель в модалке
