## Release v2.8.0

**Release Date:** October 16, 2026

Релиз **v2.8.0** относительно **v2.7.1**: последняя нода подключения по каждой ноде, дашборд в стиле Grafana, метрики нод и балансировщиков, переработанный виджет Telemt DC, мультивыбор `carriers` в Telemt, поддержка Xray-core 26.9.30 / 26.10.10 (MASQUE, XDRIVE, новые поля finalmask), постквантовое шифрование VLESS и переводы интерфейса на 11 языков.

### Что нового в двух словах

- **Клиенты:** колонка «Последняя нода подключения» теперь помнит, где клиент был в сети, по каждой ноде — и переживает перезапуск панели.
- **Дашборд:** сетка на 12 колонок, перетаскивание и изменение размера за любой край и угол, клавиатура, адаптивные брейкпоинты. Старые раскладки переносятся автоматически.
- **Метрики дашборда:** новый эндпоинт `GET /panel/api/server/dashboardMetrics`; метрики по каждой ноде и каждому балансировщику, агрегаты, шаблоны «Обзор нод» и «Обзор балансировщиков».
- **Telemt DC:** переработанный виджет — три размера карточки, история RTT, журнал изменений, уведомления, фильтры, диагностика.
- **Telemt:** `[web] carriers` — мультивыбор с порядком; каталог параметров сверен с документацией Telemt 3.5.14.
- **Xray-core 26.9.30 / 26.10.10:** MASQUE, XDRIVE, XDNS `names`/`addrs`, noise `exp`, Lua `script`, подсказки «Requires Xray ≥ …» и проверка конфигурации.
- **VLESS:** генерация постквантовых ключей (ML-KEM-768 + X25519) прямо в форме инбаунда, проверка на сервере.
- **Переводы:** интерфейс переведён на uk, es, tr, pt, id, vi, zh, tw, ja, ar, fa (машинный перевод).
- **Исправление:** убраны предупреждения консоли про preload шрифтов.

**Миграция БД:** да — `0071_client_node_presence` (новая таблица; существующие данные не меняются). Применяется автоматически при старте. Откат: вернуть прежнюю версию, таблицу можно оставить — старый код её не читает.
**Совместимость:** изменения API только аддитивные (новые поля и один новый эндпоинт), прежние поля и идентификаторы метрик не менялись. Закреплённое ядро Xray по умолчанию остаётся **v26.9.9**. Обновление затрагивает панель; ноды и образы Telemt менять не требуется.

### Последняя нода подключения по нодам

#### Что изменится

Раньше поле «Последняя нода подключения» строилось из оперативной карты «кто сейчас в сети» в памяти панели: после перезапуска или когда клиент уходил в офлайн, значение пропадало. Теперь присутствие клиента на каждой ноде хранится в базе.

#### Было и стало

| Было | Стало |
|---|---|
| Только «в сети сейчас», в памяти | Постоянная запись по каждой паре клиент–нода |
| Пропадало после перезапуска панели и ухода в офлайн | Сохраняется; видно, где клиент был и когда |
| Одна нода | Все ноды клиента с временем последней активности |

#### Как это работает

- Новая таблица `client_node_presence` (миграция `0071_client_node_presence.sql`): ключ `client_id` + `node_id`, поля `first_seen_at`, `last_seen_at`, `sessions`. Внешние ключи на `client_entities` и `nodes` с `ON DELETE CASCADE` — строки удаляются только вместе с клиентом или нодой.
- Присутствие записывается при каждом опросе нод пачечными upsert-ами: не чаще одной записи на пару клиент–нода раз в 30 секунд; счётчик `sessions` увеличивается, если между отметками прошло больше 10 минут.
- «Последняя нода» — нода с самым поздним `last_seen_at`. При равенстве выигрывает нода, на которой клиент в сети сейчас, затем нода с меньшим id.
- В интерфейсе (`ClientsPage.tsx`): имя ноды, относительное время и индикатор «в сети»; во всплывающей подсказке — все ноды клиента со временем; сортировка по времени последнего подключения.
- API аддитивно: `lastConnectedNodeAt`, `connectedNodes[]` (`nodeId`, `nodeName`, `lastSeenAt`, `online`); поле `lastConnectedNode` не изменилось.

#### Чего нельзя

- В одноузловом режиме (локальный Xray без нод) присутствие не записывается — колонка не наполняется.
- История начинается с момента обновления; прошлые подключения не восстанавливаются.

Файлы: `web/service/client_node_presence.go`, `web/service/client_traffic.go`, `web/service/node.go`, `database/model`, `panel/components/ClientsPage.tsx`.

### Дашборд как в Grafana

#### Что изменится

Конструктор дашборда получил полноценную сетку вместо прежней модели «порядок + ширина/высота». Старый `DashboardBuilder.tsx` удалён, вместо него `GridBoard`/`GridTile` и движок `panel/lib/dashboardGrid.ts`.

#### Сетка

- 12 колонок, плитка описывается как `{x, y, w, h}`; высота строки 30 px, зазор 12 px.
- Перетаскивание за заголовок плитки; изменение размера за 8 ручек (по сторонам и углам), с `Shift` сохраняется соотношение сторон.
- Плитки уплотняются вверх и раздвигаются при вставке; при перетаскивании показывается «призрачное» место, при приближении к краю окна страница прокручивается автоматически. Поддержаны сенсорные экраны.
- Клавиатура: `Alt+стрелки` — переместить плитку, `Alt+Shift+стрелки` — изменить размер; результат озвучивается через `aria-live`.
- Меню плитки: Редактировать, Дублировать (для своих панелей), На весь экран, По высоте содержимого, Сбросить размер, Удалить.
- Минимальные размеры: счётчики 2×2, графики 4×4, таблицы 4×3 (остальные виды — по типу плитки).
- Внутри плиток используются container queries: содержимое подстраивается под размер плитки, а не окна.

#### Брейкпоинты

| Ширина контейнера | Колонок |
|---|---|
| больше 760 px | 12 |
| не больше 760 px | 6 |
| не больше 640 px | 1 |

Раскладки для 6 и 1 колонки **вычисляются** из десктопной и не хранятся.

#### Перенос старых раскладок

- Сохранённые раскладки переносятся автоматически при первом открытии; признак — маркер `gridVersion` рядом с `grid`.
- Старые поля `order` и `tiles` по-прежнему записываются, поэтому откат на прежнюю версию панели не ломает раскладки.

#### Ограничения

- Редактировать раскладку можно только на десктопном брейкпоинте (12 колонок); на узких экранах показ работает, правка недоступна.

Файлы: `panel/lib/dashboardGrid.ts`, `panel/components/dashboard/GridBoard.tsx`, `GridTile.tsx`, `gridContext.ts`, `DashboardComposer.tsx`, `panel/lib/dashboardBuilder.ts`.

### Метрики нод и балансировщиков

#### Что изменится

Для своих панелей дашборда («Метрика») доступен новый источник данных — по нодам и балансировщикам.

#### Эндпоинт

- `GET /panel/api/server/dashboardMetrics` — кеш на сервере 8 секунд, выборка 8 сгруппированными запросами; к нодам и агентам не обращается: значения берутся из последней проверки состояния и опроса ресурсов.
- Право: `dashboard:read`. Разделы без прав вырезаются: узлы — без `nodes:read`, балансировщики — без `balancers:read`, аудит — без `audit:read`.

#### Что доступно

- Метрики по каждой ноде (22) и каждому балансировщику (25) с идентификаторами `node:<id>:…` и `balancer:<id>:…`, например `node:3:cpu`, `balancer:2:connections`.
- Агрегаты `nodes.*` (23 новых) и `balancers.*` (25) по всем включённым нодам и балансировщикам.
- Счётчики панели: `stats.*`, `traffic.*`, `audit.*` — 14 метрик; метрики `telemt.*`.
- Единицы измерения (в том числе `ms` и `status`); пороги warn/critical передаются как метаданные.
- Шаблоны «Обзор нод» и «Обзор балансировщиков»: по карточке на каждый объект.
- Если нода или балансировщик удалены, плитка показывает «нет данных», а редактор помечает метрику недоступной.

#### Совместимость

- Существующие идентификаторы метрик не менялись. Прежние `nodes.*` перенесены в группу каталога «Nodes (aggregates)»; сохранённые панели ссылаются на метрики по идентификатору и продолжают работать.

Файлы: `web/service/dashboard_metrics.go`, `web/controller/server.go`, `web/rbac/routes.go`, `panel/lib/dashboardMetricsCatalog.ts`, `dashboardMetricsNodes.ts`, `dashboardMetricsTemplates.ts`, `useDashboardMetricsData.ts`.

### Виджет Telemt DC

#### Интерфейс

- Карточка подстраивается под ширину: компактный, средний и крупный вид.
- Сводка и индикатор свежести данных; интервал опроса 5 / 15 / 30 / 60 с; пауза.
- Подробности по каждому DC со спарклайном RTT.
- Вспышка при смене состояния и журнал последних 20 событий; уведомления браузера — только по согласию пользователя.
- Фильтры, сортировка, группировка; подсказки по причинам недоступности; копирование диагностики.

#### Бэкенд (аддитивно)

- Дополнительно читаются `me_pool_state` и `me_quality`: по каждому DC — endpoints, writers, refill, RTT и доступность upstream; по инстансу — пул writer-ов, счётчики переподключений и сброса маршрутов, upstream-маршруты; по источнику — `latencyMs`, `fetchedAt`, `stale`.
- Кеш 4 секунды; таймаут на каждую ноду 8 секунд; при сбое ноды показываются последние известные данные (до 10 минут) с пометкой `stale`.
- Ответ старых нод (без новых полей) обрабатывается: поля опциональны.

Файлы: `panel/components/TelemtDcStatusCard.tsx`, `panel/components/telemt/*`, `node/telemt/dc_status.go`, `web/service/telemt_dc.go`.

### Параметры Telemt: `carriers`

- `[web] carriers` — мультивыбор: упорядоченные «чипы». Допустимые значения: `https`, `https-lanes`, `websocket`, `websocket-lanes`.
- Состояния: **Default** — ключ не записывается; **Disabled (false)** — записывается `carriers = false`; один или несколько значений.
- Сервер отклоняет дубли, неизвестные значения, пустой массив и `true`.
- **Семантика порядка** (сверено с документацией Telemt 3.5.14): порядок значений — порядок попыток; одиночный `carrier` добавляется Telemt один раз последним запасным вариантом (он **не игнорируется**); при `false` или отсутствии ключа используется только `carrier`.
- В каталоге параметров появился общий механизм мультивыбора (`multi`, `allowFalse`, `ordered`, `optionsFrom`); каталог генерируется `scripts/gen_telemt_catalog.py`.
- Каталог сверен с документацией Telemt 3.5.14: 428 ключей, новых ключей нет.
- В репозитории закреплён Telemt 3.5.7: 20 ключей появились начиная с 3.5.9, у двух (`web.vhosts.base_path`, `web.debug.sideband`) в каталоге стоит `since: 3.5.9`.

### Xray-core 26.9.30 и 26.10.10

Подробности и формат полей — в `docs/xray-26.10-support.md`.

#### Что поддерживается

| Функция | Мин. версия Xray |
|---|---|
| MASQUE (inbound проверяется в JSON шаблона ядра, outbound — форма в панели) | 26.9.30 |
| Транспорт XDRIVE (Google Drive и шаблонные бэкенды) | 26.9.30 |
| Noise finalmask `type: "exp"` | 26.9.30 |
| `warp.publicKey` (WARP-профиль MASQUE) | 26.10.10 |
| XDNS finalmask: `domains[].names`, `resolvers[].addrs` | 26.10.10 |
| Lua `script` для `dns` и `routing` (в JSON-схеме) | 26.10.10 |

- Хелпер версий (`panel/lib/xrayVersionFeatures.ts`) показывает подсказки «Requires Xray ≥ …». Если версия неизвестна, ничего не блокируется. Подсказки опираются на ядро самой панели, ноды с другим ядром не учитываются.
- Проверка конфигурации `lintXrayConfig(root, version)`: обязательные поля MASQUE, запрещённые заголовки, секреты Google Drive и т. п.
- WireGuard outbound: `remoteDNS: ["local"]` и `domainStrategy` помечаются как удалённые в ядре начиная с 26.9.30.

#### Что намеренно не реализовано

- MASQUE и XDRIVE как инбаунды панели и ссылки подписок (стандарта share-ссылок нет).
- Редактор Lua (панель только проверяет и подсказывает поле `script`).
- Параметры TUN.
- Автоматическая миграция старых полей конфигураций — только предупреждения.

#### Версия ядра по умолчанию

- Закреплённое ядро по умолчанию **остаётся v26.9.9** (`DockerInit.sh:66`). Селектор версий в настройках показывает 26.9.30 и 26.10.10, потому что читает релизы GitHub.
- Переход на 26.10.10 содержит несовместимое изменение в WireGuard; **сначала проверьте 26.10.10 на тестовой ноде**.

### Постквантовое шифрование VLESS

- В форме VLESS-инбаунда появился блок «Постквантовое шифрование» (`VlessEncryptionSection`).
- Кнопка «Сгенерировать» вызывает `GET /panel/api/server/getNewVlessEnc` и возвращает пару: decryption (сервер) и encryption (клиент). Варианты ML-KEM-768 + X25519 и X25519.
- Расширенные настройки: метод (`native` / `xorpub` / `random`), время жизни тикета, 0-RTT / 1-RTT, padding.
- Кнопки копирования; перегенерация — с подтверждением; ручной ввод с проверкой формата.
- Сервер проверяет значения при добавлении и изменении инбаунда (`ValidateVLESSEncryptionSettings`): отклоняет некорректные строки и постквантовое decryption при пустом или `none` клиентском encryption.
- Если на хосте панели нет бинарника xray, ключи генерирует сама панель на Go (`crypto/ecdh`, `crypto/mlkem`).
- Ссылки подписок и JSON-подписки уже читают `settings.encryption` — без изменений.
- Нельзя включить, пока у инбаунда есть fallback-и. Правило про flow `vision` не менялось.

Файлы: `web/service/vless_enc.go`, `panel/components/inbounds/VlessEncryptionSection.tsx`, `panel/lib/vlessEncryption.ts`.

- Файлы `web/translation/translate.<язык>.toml` для 11 языков (uk, es, tr, pt, id, vi, zh, tw, ja, ar, fa) дополнены **1693 ключами на язык**. - Перевод машинный, носителями языка **не проверялся**.

### Изменения API

Все изменения аддитивные.

| Метод | Изменение |
|---|---|
| `GET /panel/api/server/dashboardMetrics` | **Новый.** Кеш 8 с; право `dashboard:read`; разделы узлов, балансировщиков и аудита вырезаются без `nodes:read` / `balancers:read` / `audit:read` |
| Список клиентов | Новые поля `lastConnectedNodeAt` и `connectedNodes[]` (`nodeId`, `nodeName`, `lastSeenAt`, `online`); `lastConnectedNode` без изменений |
| `GET /panel/api/inbounds/telemtDcStatus` | Новые опциональные поля: по источнику `latencyMs`, `fetchedAt`, `stale`; по инстансу `detail`, `snapshotAt`, `writers`, `pool`, `meQuality`, расширенный `upstreams`; по DC `availablePct`, `floorMin/Target/Max`, `endpointList[]`, `upstreamRttMs`, `refillInflight` и др. Кеш ~4 с, таймаут ноды 8 с |
| Добавление / изменение инбаунда | Для VLESS проверяется `encryption`/`decryption`; некорректные значения отклоняются |

Эндпоинт `GET /panel/api/server/getNewVlessEnc` использует форма VLESS. Описание — в `web/docs/API.md`.

### Известные ограничения

- Редактирование раскладки дашборда доступно только на десктопной ширине (12 колонок); на планшете и телефоне раскладка выводится, но не правится.
- Пороги компактного / среднего / крупного вида виджета Telemt DC — эвристики по ширине контейнера и могут потребовать подстройки.
- Присутствие клиентов по нодам не записывается в одноузловом режиме.
