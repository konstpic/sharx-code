## Release v1.7.28

**Release Date:** September 19, 2026

Релиз **v1.7.28** относительно **v1.7.27**: режим WEB для Telemt теперь работает в схемах, где порт 443 занят Xray или nginx.

**Миграция БД:** нет (новые поля хранятся в настройках инбаунда).

---

### Fix: `public_addr` брал порт из Front port, из-за чего Telemt падал

**Root cause:** Telemt требует, чтобы `[[web.vhosts]].public_addr` был конкретным адресом на порту 443 (иначе `Config error: web.vhosts[0].public_addr must be a concrete socket address on port 443` и краш-луп). Панель же собирала `public_addr` как «IP:Front port», поэтому при Front port ≠ 443 конфиг оказывался невалидным.

**Fix:** `public_addr` теперь всегда `IP:443`. Front port по-прежнему определяет только порт, на котором слушает встроенный фронт SharX.

### Feature: настраиваемый порт приватного listener

Порт `[[server.listeners]]` (loopback, куда фронт или внешний терминатор проксирует трафик) раньше был жёстко `28100 + ID инбаунда`. Теперь в настройках WEB есть необязательное поле **Private listener port** (1024–65535). Пустое поле оставляет прежнюю формулу. Значение вне диапазона возвращает ошибку при сохранении, а не подменяется молча. Уникальность порта между инбаундами панель не проверяет.

### Feature: внешний TLS-терминатор (nginx / Xray fallback)

Новый чекбокс **External TLS terminator**. Когда он включён, SharX не запускает свой фронт и не занимает порт 443; конфиг Telemt строится как обычно (`public_addr = IP:443`, listener на `127.0.0.1:<порт>`). Подходит для схемы:

`клиент :443 → Xray Reality → fallback 127.0.0.1:9000 (xver 1) → nginx (TLS) → 127.0.0.1:<Private listener port> → Telemt WEB`

Раньше во встроенном режиме фронт после перезапуска занимал 443 первым, и Xray не мог стартовать (`address already in use`). Домен по-прежнему должен резолвиться в публичный IP сервера. Настройка nginx остаётся на стороне оператора.
