## Release v1.7.30

**Release Date:** September 23, 2026

Релиз **v1.7.30** относительно **v1.7.29**: исправлен мастер автоустановки ноды по SSH — после успешных SSH-шагов он навсегда зависал на «Установлено — проверяем соединение…» и не доходил до создания ноды и выбора профиля.

**Миграция БД:** нет.

---

### Fix: автоустановка ноды по SSH зависала после последнего шага

**Симптом:** все шаги (подключение, проверка/установка Docker, запись `docker-compose.yml`, запуск контейнеров) отмечались как «Готово», интерфейс переходил в состояние «Установлено — проверяем соединение…» — и на этом всё, без ошибки и без прогресса.

**Root cause — сразу два независимых бага в одном участке кода:**

1. Сразу после успешного `node/add` код синхронно вызывал `runRegisterRef.current(true)`, но `setPendingReg(...)` на предыдущей строке ещё не применился (React обновляет состояние асинхронно) — вызов уходил в **старую** версию функции, всё ещё видевшую `pendingReg = null`, и та молча выходила по своей же защите от вызова без данных.
2. Попытка починить это через чтение состояния сразу после `setState` с помощью приёма `setState(cur => {...})` тоже не сработала: React не гарантирует, что функция-апдейтер выполнится синхронно в момент вызова — она может быть применена позже, при следующем рендере. Из-за этого проверка «шаги точно завершились успехом?» иногда возвращала `false`, даже когда сервер уже отдал `success`, и код выходил из мастера до вызова `node/add`.

**Fix:** оба места переписаны так, чтобы не полагаться на тайминг React-состояния:
- функция опроса статуса SSH-задачи теперь явно **возвращает** финальный статус (`success`/`error`) как значение промиса, а не полагается на то, что вызывающий код потом правильно прочитает его из состояния;
- общий хвост «проверить ноду → назначить профиль / закрыть мастер» вынесен в отдельную функцию, принимающую данные о созданной ноде **параметром**, а не через `pendingReg` из замыкания — автоустановка по SSH передаёт эти данные напрямую, без обращения к состоянию и без гонки.
