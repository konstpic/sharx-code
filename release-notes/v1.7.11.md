## Release v1.7.11

**Release Date:** September 16, 2026

Патч **v1.7.11** относительно **v1.7.10**: фикс кириллических имён клиентов в Telemt-сессиях, расширение Telemt-параметров вслед за ядром, полная поддержка WEB-режима (MTProto через HTTPS/WebSocket).

**Миграция БД:** нет (новые поля в JSON `inbounds.settings`, ключ `[access.users]` для non-ASCII имён генерируется по-новому — см. Operational Notes).

---

### Bug Fixes

- **Кириллические имена клиентов не отображались в активных сессиях Telemt** (`web/service/telemt_config.go`, `web/service/client_session.go`, `web/service/node.go`, `node/api/server.go`)
  - Telemt Control API (`GET /v1/users/{username}`) принимает только ASCII (`is_valid_username` в апстриме) и отдаёт 400 на любое другое имя, из-за чего сессии клиента тихо пропадали из ответа
  - `TelemtUsernameForClient()`: ASCII-имя используется как есть, иначе — стабильный `u<clientId>`; используется одинаково и при генерации `[access.users]`, и при поиске сессий (single-node и multi-node)
  - На `tg://` ссылки клиента не влияет — Telemt передаёт данные подключения через secret, а не username

### Features

- **Telemt: параметры вслед за ядром** (`web/service/telemt_config.go`, `panel/lib/inboundDefaults.ts`, `panel/components/InboundsPage.tsx`)
  - `server.api.auth_header`, `server.max_connections`
  - `censorship.tls_domains`, `censorship.mask_proxy_protocol`, `censorship.server_hello_delay_min_ms`/`max_ms` (валидируется против `timeouts.client_handshake × 1000`)
  - `timeouts.relay_idle_policy_v2_enabled` + `relay_client_idle_soft_secs`/`hard_secs` + `relay_idle_grace_after_downstream_activity_secs` (soft ≤ hard, grace ≤ hard)
  - `timeouts.me_one_retry`, `timeouts.me_one_timeout_ms`
  - `access.user_max_unique_ips_mode`, `access.user_max_unique_ips_window_secs`
  - `access.user_rate_limits` — лимит скорости на инбаунд (одинаковый для всех клиентов; per-client хранилища пока нет, помечено в UI и коде)
- **Telemt WEB-режим** (MTProto поверх HTTPS/WebSocket через внешний NGINX/HAProxy)
  - Генерация приватного `[[server.listeners]]` (`transport = "web"`), `[web]`, `[[web.vhosts]]`, decoy (`http_upstream` или `static_directory`), `[[web.vhosts.profiles]]`
  - UI: тумблер + поля vhost/decoy/CIDR + пример конфига внешнего nginx с подставленными значениями (SharX сам nginx не разворачивает и не управляет им)

### Operational Notes

- После обновления пересоберите/перезапустите **sharx** и **sharxnode**.
- Миграция БД не требуется.
- Для Telemt-клиентов с кириллическим/non-ASCII именем ключ в `[access.users]` изменится с самого имени на `u<clientId>` при следующей генерации конфига — это внутренний идентификатор, подписки и секреты клиентов не меняются.
- WEB-режим требует самостоятельно настроенного внешнего NGINX/HAProxy с TLS-терминацией — SharX генерирует только `config.toml` Telemt и пример nginx-конфига, сам прокси не разворачивает.

### Test plan

- [ ] Telemt-клиент с кириллическим именем → сессии отображаются в «Активные сессии» (single-node и multi-node)
- [ ] Telemt-клиент с ASCII-именем → `[access.users]` ключ не изменился (обратная совместимость)
- [ ] Новые Telemt-поля в UI → соответствующие ключи в `config.toml`, пустые поля не пишутся
- [ ] `server_hello_delay_max_ms` ≥ `client_handshake × 1000` → поля молча не пишутся
- [ ] `relay_client_idle_soft_secs` > `hard_secs` → группа не пишется
- [ ] WEB-режим: включить тумблер, заполнить vhost/decoy → в `config.toml` корректные `[web]`/`[[web.vhosts]]`/`[[web.vhosts.profiles]]`, листенер с `transport = "web"`
