## Release v1.7.2

**Release Date:** July 3, 2026

Патч **v1.7.2** относительно **v1.7.1**: исправлен docker-compose шаблон нод и нормализация `SECRET_KEY` после legacy cert-bundle.

**Миграция БД:** нет. Нормализация `panel_pairing` выполняется при чтении секрета.

---

### Bug Fixes

- **Compose ноды использует DB auth secret**
  - Источник `SECRET_KEY` — `panel_pairing.auth_secret`, тот самый persistent JWT/HMAC secret из v1.7.0.
  - Старый base64 JSON bundle с `caCertPem` / `jwtPublicKey` больше не считается валидным plain-секретом.
  - Если в БД остался только legacy bundle без `authSecret`, панель генерирует новый 128-символьный plain secret и записывает его в `auth_secret` и `secret_key`.

- **Docker-compose шаблон**
  - Убран `PANEL_URL` из шаблона ноды: он опционален, панель передаёт URL на первом `apply-config`.
  - В compose остаётся только `SECRET_KEY` и переменные Watchtower updater.

- **Node auth parser**
  - Нода больше не принимает legacy cert-bundle как секрет, если внутри нет `authSecret`.

- **Pairing address**
  - `http://` адреса нод больше не апгрейдятся принудительно в `https://`; с v1.7.x panel→node работает по HTTP + Bearer JWT.

### Operational Notes

После обновления панели до **1.7.2**:

1. Откройте **Ноды** и скопируйте новый compose / `SECRET_KEY`.
2. Если раньше в compose был длинный `eyJ...` bundle с сертификатами, замените его на новый plain `SECRET_KEY`.
3. Перезапустите workers.
