## Release v1.7.29

**Release Date:** September 23, 2026

Релиз **v1.7.29** относительно **v1.7.28**: честный календарный автосброс трафика клиента, исправлен баг с `http://` в SSH-хосте при автоустановке ноды, переименован файл бэкапа БД, новый favicon.

**Миграция БД:** да — `0053_client_traffic_reset_cadence.sql` добавляет `client_entities.traffic_reset_cadence`, `traffic_reset_day`, `last_traffic_reset_time`.

### Feature: календарный автосброс трафика клиента (по дням/неделям/месяцам)

**Проблема:** у клиента было только поле «Сброс трафика (дней)», которое хранилось в БД, но нигде не использовалось — автоматический сброс для клиентов не работал вообще, только сброс вручную кнопкой или общий сброс на уровне inbound (сразу для всех клиентов на нём).

**Решение:** в настройках клиента появился **«Автосброс трафика»**: выкл / ежедневно / еженедельно (с выбором дня недели) / ежемесячно (с выбором числа 1-31). Работает независимо от сброса на уровне inbound, по одному клиенту. Обнуляет `up`, `down` и `allTime` — так же, как кнопка «Reset traffic» вручную.

**Короткие месяцы не пропускаются, а сдвигаются.** Если выбрано число 31, а в месяце его нет (апрель — 30 дней, февраль — 28/29), сброс происходит в последний день этого месяца, а не откладывается на следующий. Иначе клиент получал бы лишний период трафика бесплатно.

### Fix: `http://` подставлялся в SSH-хост при автоустановке ноды

**Root cause:** при переходе с шага «адрес ноды» на шаг «SSH-доступ» мастер добавления ноды пересобирал адрес (что для голого IP/хоста всегда добавляет неявную схему `http://` для хранения в БД) и разбирал его обратно в поле «хост» — из-за этого поле SSH-хоста получало значение вида `http://1.2.3.4`, и SSH не мог подключиться.

**Fix:** повторный разбор адреса происходит только если админ сам изначально ввёл в поле хоста URL со схемой (`http://`/`https://`). Для голого IP/хоста поле остаётся как есть.

### Feature: гибкая настройка Telemt WEB — приватный порт и внешний TLS-терминатор

- `public_addr` в конфиге Telemt теперь всегда `IP:443`, независимо от Front port — раньше несовпадающий порт приводил к краш-лупу Telemt (`public_addr must be a concrete socket address on port 443`).
- Порт приватного `[[server.listeners]]` теперь можно задать вручную (раньше был жёстко `28100 + ID inbound'а`).
- Новый режим **External TLS terminator**: встроенный фронт SharX не запускается и не занимает 443 — подходит для схемы `Xray Reality :443 → fallback → nginx (TLS) → Telemt WEB`.

### Fix: имя файла бэкапа БД переименовано в `sharx-db-backup.sql`

Было `x-ui-db-backup.sql` — при скачивании из панели и в бэкапе через Telegram-бота. Обновлена документация API.

### Feature: новый favicon

Старая иконка (чёрный круг с белым треугольником, наследие шаблона) заменена на фирменный плавник в градиенте панели (циан → фиолетовый). Заодно исправлен баг: `/favicon.ico` отдавал 404 — у него не было отдельного маршрута на сервере (`NoRoute` обслуживал только `/panel/*`), поэтому подмена файла в сборке раньше не имела эффекта.
