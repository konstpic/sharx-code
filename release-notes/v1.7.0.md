## Release v1.7.0

**Release Date:** July 3, 2026

> ## ⚠️ КРИТИЧНОЕ ОБНОВЛЕНИЕ — для всех владельцев нод
>
> В **v1.7.0** полностью изменена схема авторизации панель ↔ ноды. Старый `SECRET_KEY` (base64 JSON с сертификатами и mTLS) **больше не используется**.
>
> **Порядок обновления (обязательно):**
> 1. Обновите **панель** до **1.7.0**.
> 2. Скопируйте новый **`SECRET_KEY`** из панели (**Ноды** → секрет pairing / docker-compose).
> 3. Пропишите его в **`SECRET_KEY`** на **каждой ноде** и перезапустите worker (`sharxnode`).
> 4. Убедитесь, что адрес ноды в панели — **`http://host:port`** (без mTLS; JWT по HTTP).
>
> Это обновление **устраняет распаривание нод при ротации SSL-сертификата панели**: auth-секрет больше не связан с `webCert` и не меняется при обновлении сертификатов UI.

Патч **v1.7.0** относительно **v1.6.9**: новый постоянный auth-секрет для нод (128 символов), без mTLS и без сертификатов в `SECRET_KEY`.

**Миграция БД:** да — `0049_panel_pairing_auth_secret.sql` (колонка `auth_secret` в `panel_pairing`).

---

### Breaking Changes

- **`SECRET_KEY` — plain-текст (128 символов)**, один на все ноды, генерируется один раз и хранится в БД навсегда.
- **Panel → node:** HTTP + JWT (HS256, Bearer).
- **Node → panel:** HMAC-SHA256 тем же секретом (логи, geo, pull-config).
- **mTLS убран** — сертификаты pairing CA больше не входят в env ноды.
- При первом старте панели **1.7.0** существующий bundle автоматически нормализуется в plain-секрет; **ноды нужно обновить вручную**.

### Features (since v1.6.9)

- **Постоянный auth-секрет нод** (`web/service/panel_pairing.go`, `node/auth/bundle.go`, миграция `0049`)
  - Не зависит от `webCert` / `webKeyFile` панели.
  - Длина секрета: **128 символов**.
  - Лог при инициализации: напоминание обновить `SECRET_KEY` на workers.

### Bug Fixes / Motivation

- Раньше HMAC/JWT могли быть связаны с pairing-материалом (PEM в bundle). При смене материала или путаницы с cert rotation ноды теряли связь с панелью. Теперь auth изолирован от TLS панели.

### Operational Notes

- **Панель и ноды должны быть на 1.7.0** (или панель 1.7.0 + ноды с новым `SECRET_KEY`).
- После обновления панели проверьте **Ноды → health** — offline/error до смены `SECRET_KEY` ожидаемы.
- `PANEL_URL` на ноде — URL панели (как раньше); ротация web-серта панели на auth **не влияет**.

### Test plan

- [ ] Обновить панель 1.7.0 → в UI новый plain `SECRET_KEY` (128 символов)

### 📦 Upgrade from v1.6.9

1. Бэкап `.env`, docker-compose и БД.
2. Обновите **панель** до **`1.7.0`** / **`latest`**.
3. Дождитесь старта → скопируйте **`SECRET_KEY`** из панели.
4. На **каждой ноде:** замените `SECRET_KEY` в compose/env, перезапустите `sharxnode`.
5. Проверьте статус нод в панели.

```yaml
services:
  sharx:
    image: {{SHARX_TAG_LATEST}}
  sharxnode:
    image: {{SHARXNODE_TAG_LATEST}}
    environment:
      SECRET_KEY: "<новый plain-секрет из панели>"
      PANEL_URL: "https://your-panel:2053/..."
  postgres:
    image: {{HARBOR_HOST}}/{{HARBOR_PROJECT}}/postgres:latest
```
