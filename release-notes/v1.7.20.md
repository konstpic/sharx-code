## Release v1.7.20

**Release Date:** September 17, 2026

Патч **v1.7.20** относительно **v1.7.19**: три новые фичи по обратной связи от комьюнити — ретеншен ревизий геофайлов, устойчивый к CGNAT IP-лимит, и best-effort гейт подписки по клиентскому приложению.

**Миграция БД:** нет — все три фичи используют существующее key-value хранилище настроек, новых таблиц/колонок не потребовалось.

---

### Контекст

По итогам обсуждения в комьюнити (см. полную переписку в тикете):

1. **Геофайлы бесконечно копятся в библиотеке** (`Gloom`) — не заходил в панель месяц, увидел десятки строк, по одной в день. Причина не в баге дедупликации: `Loyalsoldier/v2ray-rules-dat` реально обновляется почти каждый день, и панель честно создаёт новую ревизию при каждом реальном изменении контента (sha256 сверяется). Просто никогда не было чистки старых.
2. **IP-лимит ложно срабатывает на мобильном CGNAT** (собственный анализ) — `web/job/check_client_ip_limit_job.go` считал «онлайн IP» клиента из `GetStatsOnlineIpList(reset=false)`, а у этой Xray-статистики нет TTL: она копит вообще все IP с последнего рестарта/сброса. Клиент с одним реальным устройством, но частой сменой IP оператором, со временем неизбежно превышал `max_ips`.
3. **«HWID» из переписки** (`SimpoZ`) — при ближайшем разборе оказалось, что речь про уже существующий `DispatchByUA` (классификация клиента по User-Agent в `sub/ua_dispatch.go`), а не про отдельную фичу device-лимита по `x-hwid`. Запрос: не отдал признаваемое приложение — отказ; конкретное нежелательное приложение (типа INCY) — отказ; известное (Happ и т.п.) — подписка как обычно. Комьюнити само отметило (`Phlogiston`), что User-Agent тривиально подделывается — это принято как осознанное ограничение, а не недостаток реализации.

### Features

- **Ретеншен ревизий геофайлов** (`web/service/geofile_asset.go`, настройка `geofileRetentionCount`, по умолчанию 5)
  - После каждой новой загруженной ревизии (ручной или из авто-обновления) старые **неактивные** ревизии того же типа (geoip/geosite) сверх N автоматически удаляются вместе с файлами на диске.
  - Активная (применённая) ревизия никогда не удаляется, независимо от возраста.
  - UI: Xray → Geo-files → «Keep last N revisions».

- **IP-лимит с фильтром по давности** (`web/job/check_client_ip_limit_job.go`, настройка `ipLimitRecencyWindowSec`, по умолчанию 600с)
  - IP считается «онлайн» для целей лимита только если реально виден в последние N секунд; более старые записи из накопительной статистики Xray в расчёт не берутся.
  - Синтетические строки офлайн-блоклиста (`LastSeen: 0`) из фильтра осознанно исключены — админ по-прежнему видит их и может разблокировать вручную.
  - UI: Settings → recency window рядом с остальными настройками IP-лимита.

- **Гейт подписки по клиентскому приложению** (`sub/app_gate.go`, настройки `subAppGateEnable` / `subAppGateRequireKnownApp` / `subAppGateBlockedApps`)
  - Переиспользует существующую классификацию `DispatchByUA` — никакого нового протокола или заголовка.
  - `subAppGateRequireKnownApp` — отказ, если User-Agent не распознан ни как один из известных клиентов.
  - `subAppGateBlockedApps` — CSV чёрный список конкретных приложений по ключу (например `incy`), не белый — новые клиенты не ломаются по умолчанию.
  - **Явно не является защитой от подмены** — User-Agent полностью контролируется клиентом; фича отсекает только случайных нонкомплаентных клиентов и скрейперы, задокументировано и в коде, и в подсказке UI.
  - UI: Settings → «Gate subscriptions by client app».
