# SharX Balancer (выносной балансировщик)

Отдельный сервер с **HAProxy** или **nginx (stream)** перед нодами. Клиент подключается к адресу балансировщика, а тот
передаёт соединение на одну из нод, где работает тот же инбаунд. Трафик не расшифровывается: Reality, TLS, VLESS, VMess,
Trojan, Shadowsocks, Telemt и остальные протоколы работают без изменений, ссылка клиента отличается только адресом.

Архитектура и решения: [`docs/architecture/balancer.md`](../docs/architecture/balancer.md).

## Как это работает

```
клиент ──► балансировщик:ПОРТ ──(TCP/UDP насквозь)──► нода:порт инбаунда ──► Xray
```

* В панели: **Ноды → Балансировщики**. Добавляете балансировщик (название, публичный адрес, движок), ставите на сервер
  агента, затем «ставите за него» нужные инбаунды. Ноды пула берутся из назначенных инбаунду автоматически.
* Панель сама отправляет агенту конфигурацию (JWT, как для нод) и сверяет её каждые 15 секунд: смена нод инбаунда,
  порта, отключение ноды подтягиваются без действий с вашей стороны.
* Агент проверяет конфиг самим движком (`haproxy -c` / `nginx -t`), подменяет его атомарно и перезагружает без обрыва
  текущих соединений. Если конфиг не прошёл проверку, продолжает работать прежний, а ошибка видна в панели.
* После перезапуска агент сам поднимает последнюю применённую конфигурацию, панель для этого не нужна.

## Установка агента

В панели откройте «Установить на сервер» у балансировщика: там готовый `docker-compose.yml` с вашим `SECRET_KEY`.
На сервере:

```bash
docker compose up -d
```

`network_mode: host`: порты пулов открываются прямо на сервере. В файрволе сервера откройте порт агента (по умолчанию
**8080**) для панели и порты пулов для клиентов. Образ: `harbor.sharxconnect.app/sharx/sharxbalancer:latest`, собирается
вместе с релизом. Из исходников: `docker build -f balancer/Dockerfile -t sharxbalancer .` (или `docker compose build` в
этом каталоге).

| Переменная | Описание |
|---|---|
| `SECRET_KEY` | Обязательно. Тот же секрет, что у нод (Настройки → Ноды). |
| `SHARX_BALANCER_PORT` | Порт API агента (по умолчанию 8080). |
| `SHARX_BALANCER_DATA` | Каталог состояния (по умолчанию `/app/data`, том `sharx-balancer-data`). |

Адрес API агента задаётся при создании балансировщика (по умолчанию `http://<публичный адрес>:8080`). Как и у нод,
доступ к API защищён JWT с общим секретом, но канал без TLS: не выставляйте порт агента в интернет без необходимости,
ограничьте его адресом панели.

## Движки

| | HAProxy | nginx (stream) |
|---|---|---|
| TCP | да | да |
| UDP (Hysteria2, WireGuard, AmneziaWG) | нет | да |
| Проверки здоровья | активные (TCP connect каждые 3 с) | пассивные (два отказа подряд, пауза 10 с) |
| Алгоритмы | по кругу, наименьшее число соединений, по IP клиента | те же |

UDP-инбаунд можно поставить только за балансировщик с движком nginx. Панель это проверяет. Для nginx агент сам
превращает имена нод в IP при применении конфига, потому что nginx не запускается, если имя не резолвится.

## Что видит клиент в подписке

Режим выбирается для каждой пары «балансировщик + инбаунд»:

| Режим | Записи в подписке |
|---|---|
| Сначала балансировщик, затем прямые ноды (`prepend`) | балансировщик + все прямые ноды как запасной путь |
| Сначала прямые ноды, балансировщик последним (`append`) | те же записи, балансировщик в конце |
| Только балансировщик (`replace`) | адреса нод скрыты. Если балансировщик недоступен, маршрута нет |
| Не показывать балансировщик | только прямые ноды, балансировщик работает для тех, кто знает адрес |

Каждую прямую ноду можно дополнительно скрыть в настройках нод инбаунда. Несколько балансировщиков на один инбаунд
поддерживаются; режим `replace` у нескольких заменяет прямые записи всеми ими.

## Ограничения

* **IP клиента.** Без PROXY protocol ноды видят адрес балансировщика: лимиты по IP, сессии и география на нодах
  показывают его. PROXY protocol включается на пуле (`send-proxy-v2` / `proxy_protocol on`), но инбаунд должен принимать
  его (`acceptProxyProtocol`), и тогда прямые подключения к этому порту перестают работать. Используйте только с режимом
  «Только балансировщик».
* **Здоровье.** L4-проверка видит только «порт принимает соединения». Нода с зависшим Xray, но открытым портом, остаётся
  в ротации, пока порт отвечает.
* **Точка отказа.** Один балансировщик — одна точка входа. Поэтому режим по умолчанию оставляет клиенту и прямые ноды.
* **Терминация TLS** (WS/gRPC за CDN) в этой версии не поддерживается.

## API панели

`/panel/balancer/*` (сессия или API-токен): `GET list`, `POST add`, `POST update/:id`, `POST del/:id`,
`POST enable/:id`, `POST reorder`, `POST pool/save`, `POST pool/del/:id`, `POST apply/:id`, `POST refresh/:id`.

API агента: `GET /health` (без авторизации), `GET /api/v1/status`, `POST /api/v1/apply` (JWT).

## Разработка

```bash
go test ./balancer/...        # рендер конфигов, менеджер движка, разбор статистики
```

Структура: `spec/` (формат обмена панель-агент), `render/` (HAProxy и nginx), `engine/` (процесс, перезагрузка,
статистика), `api/` (HTTP API агента), `main.go`.
